# One 0.16.2：后台浮窗内存、响应与大文件实测

发布入口：`release\0.16.2\win-unpacked\One.exe`。先从托盘退出旧版，保留整个目录后启动。

## 改动

- 启动时仅准备主界面和搜索输入窗口；文件右键菜单在搜索打开后准备，“打开方式”子菜单在主菜单展示后准备。
- 闲置隐藏菜单 45 秒后释放窗口及其渲染进程，下一次使用重新准备；正在显示的菜单和搜索输入窗口保留。重复隐藏不会延长原有回收期限，父菜单关闭时不会让子菜单多驻留一个周期。
- 统一浮窗生命周期组件，退出时停止回收计时；关闭事件只清理对应窗口，避免旧回调影响新建窗口。级联菜单定位和异步操作跳过已释放的父窗口。

默认启动窗口从 4 个降为 2 个。搜索输入仍提前准备，首次菜单响应和回收后重新打开单独验证。

## 测量方式

对 0.16.1 与 0.16.2 发布包使用隔离配置和相同步骤：开启容量监控、关闭通知、不启用全局键盘/鼠标集成。统计应用自身进程树，包含 Electron 和原生辅助程序。主窗口隐藏后测量；打开搜索、右键及子菜单后再次隐藏，等待 47 秒检查回收与再次打开。不会停止或修改用户正在运行的 One。

分别记录 Windows 私有驻留（实际驻留且不共享）、私有提交，以及各进程工作集之和。工作集之和包含重复计数的共享页，不能当作整个应用的独占物理 RAM。测试原始数据位于 `work\app-memory`。

## 后台内存对照

| 场景 / 指标 | 0.16.1 | 0.16.2 |
| --- | ---: | ---: |
| 小索引，主窗口隐藏：私有驻留 | 191.5 MiB | 156.1 MiB |
| 小索引，主窗口隐藏：私有提交 | 398.4 MiB | 314.8 MiB |
| 小索引，用过菜单后隐藏 47 秒：私有驻留 | 195.9 MiB | 156.9 MiB |
| 200 万项，主窗口隐藏：私有驻留 | 1111.5 MiB | 1151.8 MiB |
| 200 万项，主窗口隐藏：私有提交 | 1411.8 MiB | 1341.0 MiB |
| 200 万项，用过菜单后隐藏 47 秒：私有驻留 | 1115.9 MiB | 1095.9 MiB |
| 200 万项，用过菜单后隐藏 47 秒：私有提交 | 1409.2 MiB | 1350.5 MiB |

小索引场景独占物理驻留下降约 19–20%。大索引场景私有提交下降约 59–71 MiB；主窗口刚隐藏时物理驻留反而增加约 40 MiB，不能宣称整个大索引软件的物理驻留稳定下降。Windows 缓存、工作集回收与进程启动顺序会影响单次测量。该对照并未证明 CPU 占用或冷启动变快；冷启动数据包含索引目录签名验证，不等同窗口显示时间。

只读检查用户当前 0.15.2 实例：20 个 One/辅助程序及所属控制台进程合计私有驻留约 1080 MiB，私有提交约 1881 MiB；其中索引约 1042 / 1426 MiB。该实例当时的负载未知，不能与隔离测试直接相减或当作纯后台基线。测试没有关闭、修改或升级该运行实例。

## 响应与回收

0.16.2 小索引：搜索原生窗口显示约 20 ms，自动化观察输入可见约 193 ms；首次右键约 92 ms，回收后再次右键约 83 ms。200 万项：搜索原生窗口显示约 17 ms，自动化观察输入可见约 447 ms；首次右键约 82 ms，回收后再次右键约 91 ms。这些是本机测试值，自动化观察数据包含工具与 IPC 开销，不等于纯绘制耗时。

菜单与“打开方式”子菜单实际隐藏 47 秒后释放，再次打开与级联显示成功，无页面异常。搜索输入窗口仍保留；再次打开菜单不会要求重建文件索引。

## 大文件校验

生成实际写入内容的两份 64 MiB 和两份 512 MiB 文件，通过发布包完成全内容重复校验；分别读取 128 MiB 和 1 GiB。对同一已确认的应用进程树，每 100 ms 采样 Windows 私有驻留及提交。文件工作线程属于主进程，已计入；极短暂的其他辅助进程不在该固定树采样中。

| 输入规模 | 完成时间 | 新增私有驻留峰值 | 新增私有提交峰值 | 校验中页面切换 | 20 ms 心跳 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2 × 64 MiB | 437 ms | 12.1 MiB | 18.5 MiB | 53 ms | 43.3 ms |
| 2 × 512 MiB | 2.25 秒 | 6.5 MiB | 11.0 MiB | 34 ms | 21.4 ms |

512 MiB 场景合计私有驻留峰值约 180 MiB、私有提交峰值约 401 MiB。结果验证两份文件完成完整校验，产生一组重复文件；并非只采样头部。第一次包含工作线程冷启动，第二次已热身，且新写文件可能在 Windows 缓存中，不能把两行直接比较为性能改善，也不能当作磁盘冷读速度。100 ms 采样可能遗漏更短的瞬时峰值。测试生成的四份大型文件已逐项删除，保留数据记录和隔离配置。

这是对当前流式实现的验证，不是本轮新增算法的前后对照。其他大型文档、目录任务与主要功能仍继续检查。

## 发布验证

- 60 项测试与类型检查通过；浮窗生命周期覆盖隐藏窗口释放、显示窗口保留、重复注册、重复隐藏不延时、快速重新打开、再次隐藏和退出时停止计时。
- 0.16.2 包内 139 项编译代码/样式和 7 个辅助程序与当前构建一致。
- 概览和四项文件工具真实操作通过，包括重命名预览/执行/撤销、规则变化后更新预览、正文索引与查询、历史跳转、SegmentTab 键盘导航。没有页面异常。
- QQ 文件/程序结果稳定、程序与系统设置筛选、级联菜单左右展开、菜单高度与滚动限制、窗口卡片等高、附着搜索底边检查通过。
- 普通退出、搜索窗口关闭后重建、预览及多级菜单显示时退出三个场景均正常退出，无主进程异常或错误弹窗。
- 旧包中复现父菜单先释放、子菜单仍有异步请求时的“Object has been destroyed”；已为窗口查找、定位与异步展示增加生命周期保护。
- 最终发布包三级快捷菜单：每级为独立窗口，父窗口先关闭后的子菜单请求安全处理；实际隐藏 47 秒后整组窗口全部释放，再次逐级展开成功，无主进程或页面异常。测试模拟该隔离实例的资源管理器事件，未安装全局输入钩子。
- 最终发布包搜索外观检查：独立窗口 64 / 560 DIP 展开与收回、附着结果位于输入上方、单行子菜单无空白尾部、系统文件/窗口图标、折叠导航 40 × 40 DIP、菜单编辑增删/撤销/嵌套、搜索按钮与 SegmentTab 对齐、预览卡片间距及 VSCode 图标均通过。
