# 代理连通性测试实现记录

2026-10-10。当前开发版扩展系统信息的代理页；使用方式见[用户指南](../../user-guide/系统信息与磁盘告警.md)，当前任务见[TODO](../../development/TODO.md)。

## 完成范围

- 增加 TikTok、X、Twitter 旧地址、Grok、Gemini、Instagram，共 20 个预置网站。
- 完整 URL / 域名、自定义地址预览、直连/代理/对比、单站重测、筛选后批量检测、取消与恢复。
- 输入与检测方式并排，底部集中操作；复用 `customControls` 自定义下拉组件及键盘操作。自定义结果与预置列表共用表头、行结构和样式。
- HEAD 与最多 5 次重定向；区分 DNS、连接、TLS、超时、HTTP 错误、登录/访问限制及代理拒绝 HTTPS 隧道，结果显示本次路由及最终地址。
- 全组共享 4 个工作槽，取消时终止 curl 子进程并丢弃排队项和过期进度；代理解析有单独超时。系统返回 DIRECT 时尊重其顺序，不回退到手动代理。
- 自定义地址仅留在本次界面内存；查询参数不进入结果、错误、进度或配置文件。更换自定义目标会清除旧目标两列结果，避免跨地址混用。

## 验证

`tests/proxy-connectivity.cjs` 使用真实系统 curl、本地 HTTP / CONNECT 代理与错误 TLS 服务验证。覆盖 200/204、401/403/407/429/451、404/405/500、重定向及循环、DNS/连接/TLS/超时、隧道拒绝、PAC DIRECT/失败/超时、环境代理优先级、20 项批量、4 并发上限、取消当前与排队项、拒绝并行任务、停止服务和敏感参数隐藏。

`tests/proxy-information-smoke.cjs` 在隔离配置的 Electron 中使用本地代理验证 20 项列表、系统信息卡片、自定义下拉与键盘、表头和列宽一致、原目标重测、筛选批量与单站、取消恢复、输入稳定和 1550 / 1000 宽度无控件溢出。不会把本地代理响应当成公网网站可用性证明。

源码检查：`npm run typecheck`；文档检查：`npm run check:docs`。测量和截图保留在 `work/current/proxy-connectivity/`；最终通过次数与取消耗时见该目录的报告，不将固定毫秒数作为产品性能承诺。

本轮验证开发源码与构建后的桌面交互，未执行安装、推送或发布。参考 [curl 官方选项](https://curl.se/docs/manpage.html)和[错误代码](https://curl.se/libcurl/c/libcurl-errors.html)；网站限制和 HEAD 行为可能随服务变化。
