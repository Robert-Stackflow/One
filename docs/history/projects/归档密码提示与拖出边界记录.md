# 归档密码提示与拖出边界记录

2026-10-10，在真实开发窗口中检查归档拖出与加密包恢复流程。修复未填写密码时直接显示 `Password required` 的问题，并将无法确定原因的打开失败转换为中文排查提示。没有将密码错误与损坏包强行区分。

## 密码提示与恢复

`src/main/archive-service.ts` 共用诊断转换新增两项：需要密码时指向“密码与编码”；无法打开时列出格式、分卷完整性及密码三项检查。原生错误码和 CLI 原始诊断未改变。

使用真实 One 开发窗口与外部 7-Zip 制作的 LZMA2 固实、加密头部 7Z 样本，观察到修复前的英文错误。更新后通过 Windows UI Automation 操作确认：

1. 未填写密码时显示中文填写入口指引。
2. 填写公开测试用的错误密码并应用后，显示中文综合排查提示。
3. 更正密码后重新读取成功，根目录显示文件夹与 `root.txt`。

现有 `test:archive-seven-diagnostics` 补充真实服务断言：单卷及分卷的缺密码/错误密码四次调用，以及 AES ZIP 缺密码校验调用。原有三种加密、12 个损坏输入、36 次失败操作、六次输出哈希和独占卷检查继续保留。另完成类型检查与密码、ZIPX 密码、拖出协议、格式四组回归。结果见 [测量证据](measurements/archive-password-prompts.json)。

## 拖出验证的范围

实际使用鼠标手势将已选文件夹和根文件拖向 One 窗口内的空白区域，没有有效接收目标。界面显示“已取消拖出”；该样本唯一的任务记录为 `cancelled`、数量 0，未生成输出，本次样本没有残留拖出缓存记录。此结果证明界面到真实辅助进程的取消流程，未观察到是否进入 `DoDragDrop`，不据此宣称 OLE 投放通过。

另为资源管理器准备了独立接收目录，尝试跨窗口投放前，computer-use 工具拒绝了源窗口范围之外的终点坐标。错误为 `point (1297, 536) is outside window bounds`，源窗口尺寸为 1242×842。此动作没有实际投放，因此 Explorer、第三方程序接收、完整输出结构与哈希仍未验收；安装版和跨权限范围也保持待办。

本轮新增的资源管理器窗口已关闭，原有窗口保留。ZIP、加密 7Z、中文及 emoji 文件、嵌套和空目录样本保留在 `work/current/archive-real-drop/`，供后续实际投放验收；没有通过其他输入方式绕过工具限制。文字观察、相关任务摘录及日志由 `verification/archive-password-prompts/latest.json` 绑定提交和哈希。未额外保存截图文件，也不据此声称客户端历史截图已移除。
