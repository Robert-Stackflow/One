# 归档十万小文件优化记录

本阶段以提交 `81c0e75` 的已构建归档辅助程序为基线，优化源码与本文同一提交。当前待办仍见[开发状态与待办](../../development/TODO.md)。本页记录 ZIP 小文件解压的目录复用，以及真实服务的解压、发布与清理测量。

## 环境与方法

Windows 11 专业版 26200、AMD Ryzen 9 7940HX，D 盘 NTFS 固定卷；继承开发进程权限，未提权。线程 2、内存预算 1,024 MiB，真实 `ArchiveService`、原生辅助程序与共享预算组件，独立 profile，每次使用新目标目录。两版使用相同归档、权限和设置；没有清空 Windows 文件缓存，也没有冻结系统背景负载。第二轮基线发布期间运行过少量短时目录单元编译与测试，没有同时运行完整构建或其他归档测试。因此结果是本机开发测量，不是冷盘或隔离实验室结果。

数据由 Python 标准库生成：100,000 个非空 Deflate 文件，分布在 1,000 个交错分支，含中文路径；每项 256 字节，总输出 25,600,000 字节，ZIP 大小 18,710,833 字节，使用 ZIP64 条目数量。内容是每个序号独立的 SHA-256 块重复八次，是可复现的合成小文件，不能代表真实文件的压缩熵或大文件吞吐。

“解压到新文件夹”与“解压到当前位置”各测两次。十万项正常触发风险预检，确认前要求输出目录仅包含既有 `keep.txt`；确认使用绑定归档版本的 64 GiB / 30 分钟限制。预检单独记录，完成时间从确认后的请求开始，包含服务与原生解压，以及当前位置模式的事务发布。不会绕过风险检查或放宽默认产品规则。

每轮完成后独立读取全部 100,000 文件，按生成算法核对长度和 SHA-256，检查既有文件及暂存/恢复目录清理；哈希核对与测试输出目录删除时间另计。记录原生进程的 OS 工作集/提交内存峰值、20 ms 采样私有内存、用户/内核 CPU 时间及逻辑 I/O；逻辑读取字节不等于物理磁盘读取量，“其他 I/O”包含非读写请求。Node 内存是请求结束时快照，不是峰值。未单独测量目录创建时长、物理设备吞吐、桌面渲染器或安装版性能。源文件没有 Zone.Identifier，来源传播开启、AMSI 扫描关闭；下载来源和扫描成本由功能回归验证，不包含在性能数字中。

## 测量结果

前后共八轮请求、800,000 个输出文件均通过独立长度/哈希核对，既有文件保留且无暂存/恢复目录残留。时间为各组中位数，内存为组内最大 OS 峰值；完整分组、数据及三份原生组件哈希见[测量数据](../measurements/archive-small-files.json)。

| 当前位置完整请求，秒（各两轮） | 467.293 → 458.085 |

目录复用减少了约 89.7% 的其他逻辑 I/O 请求，新文件夹完成时间有明确下降，进程工作集基本持平。逻辑读取量没有下降；没有测量物理磁盘吞吐，不能把逻辑读取字节解释为设备实际读取量。

当前位置模式的基线两轮为 486.215 / 448.371 秒，优化后为 463.555 / 452.614 秒，范围相互重叠；发布仍占主要耗时，其中位数基本持平。本阶段不将完整请求约 2% 的变化解释为发布优化，发布路径仍需独立分析。四轮测试输出目录的额外删除时间累计为基线 29.577 秒、优化后 29.297 秒，不计入请求完成时间。

## 实现与边界

ZIP 解压改为复用最多 4,096 个缓存目录节点，避免每个小文件重复遍历并查询全部父目录。缓存节点持有实际目录句柄，活动输出保留父链；缓存淘汰不会解除活动输出所需的锁。暂存目录使用目录读取权限及限制共享，拒绝链接与不兼容文件。仅读取属性不足以可靠阻止叶目录重命名，这一情况已由真实 Windows 重命名测试发现并覆盖。

创建暂存根目录时短暂锁定直接父目录，验证祖先目录及父目录身份，然后以独占方式创建并锁定根目录。长期祖先句柄仅读取属性，避免锁住无关任务的目录内容；测试覆盖兄弟目录和另一个活动任务下的发布。此目录复用仅接入 ZIP，其他格式的目录创建路径未作同类优化。ZIP 的直接原生解压拒绝含目录链接的原始目标祖先路径；普通目录目标、选择解压、预览和拖出均经回归验证。

暂存根存在且被锁定时，祖先目录保持非空；Windows 的 [FSCTL_SET_REPARSE_POINT](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/fsctl-set-reparse-point) 拒绝为非空目录设置重解析点。目录重命名与无关目录发布另外通过本机真实 API 检查覆盖。

文件仍逐项以独占方式创建，执行原有大小、CRC/认证、空间、取消及风险限制。当前位置模式继续逐文件核对身份、写入恢复日志、提交与回滚，本阶段没有调整其持久化屏障或发布协议。

## 验证与复现

`npm run test:archive-directories` 执行严格告警编译与普通/ASan 两轮，各 212 项检查，覆盖真实 junction、越界、独占暂存、缓存淘汰、目录锁、并发创建、无关目录发布与句柄释放。真实十万项取消验证在输出 1,220 项时取消，原生进程退出和暂存清理完成用时 153.5 毫秒，既有文件保留。

完整应用构建及类型检查通过；最终原生源重新编译通过，严格目录测试无告警，归档源 `/W4` 仅保留三条既有警告。原生基础、浏览、认证、风险、空间、来源、扫描、发布、日志、恢复、修改、格式及 CLI 回归均通过。文档检查通过。

```powershell
python tests/archive-small-files-benchmark.py # Python 3.11+
node tests/archive-small-files-benchmark.cjs --label current --repeat 2
node tests/archive-small-files-cancel.cjs
npm run test:archive-directories
```

前后对照时用 `--helper-dir` 指定独立保存的已构建辅助程序目录，包含 `One.Archive.exe`、`One.ArchiveBudget.dll` 和 `7z.dll`。原始测量位于 `work/current/archive-small-files-perf/`，精选证据位于 `verification/archive-small-files/latest.json`。生成归档可复用；每轮测试仅删除本次拥有的输出目录，加载中的共享预算 DLL 保存在测试临时 profile 之外。

超大固实包、混合任务、慢盘及网络盘仍需独立验收；本阶段结果不代表全部归档性能目标完成。
