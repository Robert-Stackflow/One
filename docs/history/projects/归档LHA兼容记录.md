# 归档 LHA 兼容记录

本阶段补齐 LHA/LZH level 3 读取和文件名代码页。此前 7-Zip 处理器明确拒绝 level 3，并统一按系统 OEM 编码转换名称；带 CP932 标记的既有样本也会在本机显示乱码。实现为本记录所在提交，原始记录位于 `work/current/archive-lha/`，组件及检查对应关系保存在 `verification/archive-lha/latest.json`。

## 实现与范围

随包 7-Zip 26.04 保持固定源码，另提供 `one-lha-headers.patch`，与 ZIP 密码补丁顺序应用。构建缓存版本由源码和两份补丁共同决定；安装包的对应源码清单和第三方声明也包含新补丁。

level 3 读取四字节长度字段，完整头部限制为 1 MiB、最多 256 个扩展。先核对尺寸、链边界和存在的公共头部 CRC，再接受条目；时间按 Unix 时间解释。超过 64 KiB 的扩展有独立有效用例，其他字长和越界、截断、重复 CRC 等损坏情况拒绝读取。扩展布局与 CRC 处理参照固定版本的 [Lhasa 原始读取源码](https://github.com/fragglet/lhasa/blob/75ed83559f23e9538e0045c62f53f77ab03d03d6/lib/lha_file_header.c)核对，产品解码仍使用 7-Zip 自身的 LHA 编解码器。

“自动”优先采用包内 `0x46` 代码页标记，未指定时沿用 OEM 编码；无效 Windows 代码页拒读。显式 CP437/932/936/949/950/UTF-8 覆盖包内标记，便于处理错误标记。Unicode 转换后再处理路径，CP932 “表”的尾字节 `0x5c` 不会误作目录分隔符。浏览、普通列表、详情、校验、选择解压及 OLE 拖出均传递同一文件名编码；密码编码保持独立。

Unix 权限扩展作为 POSIX 属性提供给现有预检，即使链接使用普通文件名，也拒绝将其解压或拖出。不安全路径仍拒绝提取；原始元数据列表可以检查部分不安全名称，界面浏览沿用原有路径检查。level 0/1/2 的二进制头部读取和现有解码方法保持原实现。本次不提供 LHA 写入，也不恢复 OS/2 扩展属性。

## 样本与独立核对

| 数据 | 核对范围 |
| --- | --- |
| Lhasa 固定提交的四份 OS/2 v2.08 实际写入器样本 | `lha a -arde` 生成的 level 3：存储、压缩、长文件名和嵌套目录；4 个输出文件的名称、长度、SHA-256 和时间 |
| 既有 libarchive level 3 样本 | 两个普通文件及目录，独立输出哈希；实际没有链接，现由不支持用例改为正向读取用例 |
| 既有 libarchive CP932 样本 | “漢字.txt”和“表.txt”的自动及手动编码、原索引、选择解压和内容哈希 |

四份 OS/2 归档来自 [Lhasa 的实际工具样本目录](https://github.com/fragglet/lhasa/tree/75ed83559f23e9538e0045c62f53f77ab03d03d6/test/archives/lha_os2_208)，源码下载 SHA-256、归档字节及输出期望见 [LHA 样本清单](../../../tests/fixtures/archives/lha/manifest.json)。原始工具说明和 ISC 声明一并保留。既有 libarchive 的固定提交及许可证仍见父目录说明。

独立参考为本机 Windows `bsdtar` / libarchive 3.8.8，实际程序哈希和完整版本写入清单；CP932 参考指定 `lha:hdrcharset=CP932`。期望值来自参考程序实际提取，不以产品自己的输出作为期望。Python 控制台因编码可能显示替代字符，保存的文件名和清单已按 Unicode 码位确认。产品测试离线使用这些固定期望，不依赖系统参考程序。

## 验证与复现

`test:archive-lha` 通过 131 项检查，包括真实样本、六种显式代码页、自动标记及手动覆盖、无效标记、元数据时间、完整/单项/文件夹选择解压、OLE 描述符/流的名称和字节哈希、32 位扩展、头 CRC、边界、路径和链接拒绝。嵌套 `.gz` 文件正常触发风险确认，确认前不写输出；测试绑定原包版本后继续。

桌面验证通过四份实际 level 3 样本的浏览和校验、嵌套目录导航及提取，以及 CP932 自动显示、手动应用、搜索、详情和选中项提取；输出按独立哈希核对。测试等待详情弹窗关闭后才编辑目标目录，避免向仍被模态窗口隔离的表单发送输入。

完整应用构建和最终 DLL 重建通过。格式回归通过 173 项，浏览、原生基础、拖出、认证 172 项、ZIPX 密码 430 项和独立控制台 CLI 回归通过；CLI 新增真实 level 3 及 CP932 的列表、校验和输出哈希检查。对应源码安装包过滤清单覆盖两份补丁，文档检查通过。

```powershell
npm run build
npm run test:archive-lha
node tests/archive-lha-ui.cjs
npm run test:archive-formats
node tests/archive-cli.cjs
```

本机为 Windows 11 build 26200、x64、开发版 NTFS 场景。OLE 数据对象检查不等于真实 Explorer 或第三方接收程序验收；更多旧工具、文件名扩展和方法组合、其他文件系统及安装版仍待推进。本阶段没有用小样本推断大型 LHA 的性能。
