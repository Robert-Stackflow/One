# 归档 RAR 兼容记录

本阶段补齐 RAR 非英文密码、加密及分卷的交叉验收。当前随包引擎已正确处理这些组合，因此没有修改产品引擎或密码转换。新增固定样本、离线回归、真实桌面及控制台入口，并把产品检查接入 `test:archive`。本记录所在提交保存测试与文档；组件哈希、工具来源和检查结果在 `verification/archive-rar-matrix/latest.json`，原始日志保留于 `work/current/archive-rar-matrix/`。

## 固定样本与独立核对

从 [RARLAB 官方 RAR 6.24 包](https://www.rarlab.com/rar/winrar-x64-624.exe) 解出控制台工具，仅用于制作和独立校验，未安装或随产品分发。选择这个固定版本以同时写入 RAR4/5；软件包和工具 SHA-256 在[样本清单](../../../tests/fixtures/rar/matrix/manifest.json)中。开发者重制脚本核对工具哈希、拒绝非空输出目录，避免无意更新旧卷。

矩阵为 RAR4/5 × 数据/头部加密 × 普通/固实 × 单卷/两卷，共 16 组、24 个卷。RAR4 分卷使用旧式 `.rar/.r00`，RAR5 使用 `.part1.rar/.part2.rar`。公开测试密码含中日韩字符、emoji 代理对及重音字符；四个文件共 48,000 字节，由独立于归档引擎的固定 SHA-256 规则生成，名称包含中文嵌套目录、日文“表”、韩文和 emoji。

官方 RAR 对全部样本执行完整性检查及解压；安装的 7-Zip 25.01 也独立检查并解压 16 组。两者都核对四个负载的尺寸与 SHA-256，7-Zip 共核对 64 个输出。固定归档每卷另有尺寸与 SHA-256。日常回归直接使用本仓库样本，无需安装写入器或联网。

## 产品验证

`npm run test:archive-rar-matrix` 通过 400 项分组检查：

- 数据加密包可不输入密码列目录；加密头必须提供密码。正确密码可读取 Unicode 名称、详细信息及完整性结果，名称编码选项不改变已保存的 Unicode 名称。RAR 拒绝 ZIP 专用密码编码选项。
- 16 组均完成完整、指定文件和指定文件夹解压，核对输出集合、字节数与独立哈希；原生 OLE 数据对象的指定文件流核对名称、长度及 FNV-1a，未将此检查描述为实际 Explorer 拖拽。
- 错误密码及规范分解后外观相近的不同密码拒绝解密；错误密码解压没有发布文件。缺卷、从后续卷打开、卷修改时间变化、后续卷截断或数据篡改均拒绝相应操作，失败后目标目录为空。
- 各组结束后核对所有归档卷的内容哈希，测试暂存按限定目录清理。

`npm run test:archive-rar-matrix-ui` 通过四个真实桌面流程：RAR4/5 普通数据加密单卷和固实加密头分卷，填写 Unicode 密码、显示只读入口、隐藏 ZIP 密码编码、完整性测试、完整解压及 emoji 文件单独解压，输出集合和哈希一致。`tests/archive-cli.cjs` 另验证 RAR4/5 固实加密头分卷：无密码退出码、标准输入密码、JSON 列表、校验及实际解压，输出未回显密码。

既有 `tests/archive-rar.cjs` 与 `tests/archive-rar-comments.cjs` 也通过，继续覆盖混合密码、原有上游分卷、损坏诊断和 RAR 备注。此阶段没有产品源码变化，沿用上一阶段已构建组件，不重复完整构建或无关格式测试。

既有 RAR 回归首次运行在新文件夹提交时遇到一次 Windows `EPERM` 目录改名错误，同一测试仅重试一次后通过；首次失败日志另存为 `rar-first-failure.log`。尚未取得占用来源证据，不能归因于扫描软件或声称已修复；新文件夹发布的短暂文件系统占用列为后续排查项。

## 仍待推进

结果只代表固定写入器、非空文件、单卷/两卷、本机磁盘和开发版。旧写入器及非 Unicode 名称、更多卷数量/结构、恢复卷/SFX、网络盘、硬件断电、实际外部拖拽及安装版保持待验收。加密头中的 RAR4 备注及加密/分割 CMT 的现有限制保持不变。RAR 创建和修改不在产品能力范围内。
