# 归档加密固实分卷与回收修复记录

## 问题与修复

在 `2dde349` 的组件上验证加密大固实包时，原生 7Z 提取正确返回 `timeout`，却留下刚创建的空目标目录。另一份独立 Copy 7Z 样本证明，CRC 错误、数据错密及最终空间检查失败还会留下已经写入的文件。应用服务的外层清理会回收它们，原生提取函数自身此前没有失败回收。

`native/archive/sevenzip.cpp` 现在以成功创建目录作为所有权边界：目录不存在且创建成功后才由作用域守卫负责回收，成功完成提取及最终空间检查后保留；已有目录或文件拒绝提取且保持完整。提取回调改为自动释放，异常路径也先关闭输出流，再回收目录。删除失败时记录诊断，保留原有错误；服务层的暂存清理继续有效。

该保护位于共用的 `seven_extract` 函数内部，涵盖其解码和最终空间检查失败，不承诺代替函数返回后的源修订检查、来源标记、扫描或外层发布清理。原生 ZIP 的暂存行为未在本阶段改动。现有空间故障测试相应改为要求原生 7Z 的失败目录不存在。

## 独立加密样本

官方 7-Zip 25.01 分别创建 LZMA、LZMA2 的单卷及分卷四份样本，字典 16 MiB、单固实块、数据和标头加密，使用含中文及 emoji 的测试密码。分卷大小 32 KiB，各五卷。输入为 32 MiB、512 MiB、1 KiB 三个非空确定性文件，合计 544 MiB + 1 KiB；哈希生成的数据块重复使用，逐 MiB 改写计数。外部工具确认方法、字典、单块结构并完整校验通过。

写入器、输入、12 个归档卷及冻结组件哈希、修复前残留和最终结果见[测量数据](measurements/archive-solid-volumes.json)。负载用于验证大前缀解码和卷边界，不代表真实文件压缩率或磁盘吞吐。

| 验证 | 最终结果 |
| --- | --- |
| 原生选择尾项 | 四组均只有 `1/1` 完成进度；1 KiB 输出 SHA-256 正确；约 331–364 ms。 |
| 原生及 OLE 前缀时间预算 | 10 ms 预算均返回 `timeout`、没有成功结果和遗留目录；包含启动及加密开销的实际返回约 33–86 ms。 |
| OLE 内容流 | 四组尾项均通过实际字节数及独立 FNV-1a 核对。 |
| 服务取消及重试 | 收到提取开始通知约 50 ms 后请求取消，取消请求至返回约 2–14 ms；父目录为空，随后立即重试成功。 |
| 服务时间预算 | 100 ms 预算实际约 114–124 ms 返回超时，未发布输出。 |
| 完整输出 | 四组共 12 个完整文件 SHA-256 正确。连同原生及服务的尾项选择，共 20 次 SHA-256 核对。 |
| 缺中间卷、缺末卷、截断末卷、修改中间卷 | 两组分卷各四场景均拒绝提取，返回 `archive`，输出父目录为空；原始卷保持完整。 |

预算由回调与服务计时器检查，包含启动、元数据及加密开销，不是硬实时保证。卷错误的进一步定位提示、更多参数/卷结构、超过 4 GiB 的加密分卷组合、慢盘及网络盘未由本阶段证明。

## 原生失败回收对照

`tests/archive-seven-cleanup.cjs` 使用两份独立创建的 2 MiB Copy 7Z，核对 CRC 已损坏时外部校验确实失败。冻结旧程序在第二项 CRC 错误后留下两个文件，第一项哈希正确；数据错密后留下第一项；最终空间检查失败后留下两个完整输出。修复后的最终构建在这三种失败下都删除新建目录，并继续正确返回 `archive/archive/write`，没有成功结果。

正常提取的两个输出 SHA-256 正确；已有目录中的哨兵文件、已有同名文件及源归档都保持完整。加密大样本另证明原生超时失败目录也被回收。对照使用真实原生程序和实际文件写入，未通过模拟调用替代。

## 构建、回归与复现

完整构建通过。原生失败回收及加密大包、固实、真实桌面、格式、LHA、RAR、RAR 400 项矩阵、原生接口、详情、拖出、空间、风险和真实 CLI 共 14 组相关验证通过。空间组首次停在旧的“检查 7Z 残留文件尺寸”断言，更新为失败目录不存在后通过；两次日志均保留。

`npm run test:archive-seven-cleanup -- --writer <官方7z.exe绝对路径>` 运行小型回归；`--native <旧程序路径> --baseline` 可核对旧行为，`--report <新文件路径>` 保存摘要。`npm run test:archive-solid-volumes -- <官方7z.exe绝对路径> <work/current下的新目录>` 生成并验证大样本；已有样本可通过 `--verify --label <新标签>` 使用当前构建并冻结组件，报告与组件目录均拒绝覆盖。这两个入口需要外部写入器，未加入默认离线测试集合。

本地证据位于 `work/current/archive-solid-volumes/`：`baseline-cleanup-report.json`、`cleanup-baseline.json`、`cleanup-fixed.json`、`final-report.json` 和 `checks/results.json`。原生构建、完整构建及各阶段日志位于同级工作目录上层，以 `archive-solid-volumes-` 开头。原始输入、所有展开输出及测试进程已释放；保留压缩卷、冻结组件和小份日志供后续定位使用。
