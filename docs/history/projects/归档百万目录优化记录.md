# 归档百万目录优化记录

本阶段以提交 `68543d0` 的已构建 helper 为基线，优化源码与本文同一提交。当前待办仍见[开发状态与待办](../../development/TODO.md)，本页只记录这一阶段的源码与开发版结果。

## 环境与方法

Windows 本机 AMD Ryzen 9 7940HX，16 核 / 32 线程，D 盘 NTFS 固定卷；设备吞吐未单独标定。继承当前开发进程权限，桌面主进程为 medium，未请求提权；线程 2、内存预算 1,024 MiB。ZIP 目录来自 One + minizip-ng 4.1.2，已有本地补丁保持不变，7-Zip 26.04 未修改。

两个流式生成的有效 ZIP64 各含 1,000,000 个空的 Store 常规文件：一个平铺根目录，一个位于共享目录的 1,000 个分支中；条目插入顺序经过固定置换。它们验证元数据浏览，不能代表解压文件创建、压缩吞吐或真实大载荷。每页 200 行，每种场景使用全新的 helper 测两次；记录首次观测与重复请求，Windows 文件缓存未清空，不称为冷盘测试。两轮使用同一份数据、设置和权限。

## 原生辅助进程结果

时间为两次完整请求的中位数，内存为两次 OS 峰值的最大值。工作集、提交内存和 10 ms 采样的私有内存分别记录；原始分组指标及数据、helper 哈希见[结构化测量](../measurements/archive-browser-million.json)。

| 场景 | 完成时间，秒（前 → 后） | 峰值工作集，MiB（前 → 后） | 峰值提交内存，MiB（前 → 后） |
| --- | --- | --- | --- |
| 根目录首屏 | 1.857 → 1.922 | 352.4 → 237.6 | 361.2 → 240.2 |
| 全部文件首屏 | 1.827 → 0.963 | 352.3 → 178.8 | 361.2 → 210.0 |
| 全部文件末页 | 2.003 → 0.934 | 352.4 → 178.9 | 361.2 → 210.1 |
| 搜索 1,000 个匹配 | 1.025 → 0.882 | 136.1 → 8.4 | 156.5 → 1.9 |
| 深层归档根目录 | 1.110 → 0.980 | 146.9 → 8.4 | 167.1 → 1.6 |
| 深层归档全部文件 | 2.282 → 1.225 | 398.1 → 189.7 | 405.0 → 220.4 |
| 深层目录导航 | 1.018 → 0.925 | 146.9 → 8.4 | 167.0 → 1.9 |

普通根目录耗时基本持平且略增，峰值工作集下降约三分之一；全部文件首屏、末页和深层全部文件约减少一半时间与工作集。搜索、少量顶层目录和目录导航不再为未显示的百万条目保留 ZIP Entry 副本。

ZIP 浏览改为访问一个条目后直接交给浏览器收集。搜索与全部文件模式使用紧凑行数组，保留原始名称和索引，只选择、排序请求的页；普通文件夹模式保留原有去重和显式目录覆盖隐式目录的语义。所有路径仍在返回页面前验证，页外的恶意路径也会拒绝整次浏览。

## 桌面与正确性

14 个基线/优化请求的元数据和完整返回条目逐项一致，原始索引另按生成置换独立核对。36 个小型独立页面对照覆盖重复路径、字典序索引、反斜杠名称、显式/隐式目录、Unicode 搜索、末页、越界与空页；页外恶意条目拒绝通过。ZIP 基础/修改写回、文件夹编辑、格式 168、ALZ 138/分卷 94/变体 151、EGG 274 及命令行回归通过。完整构建通过；browse.cpp 的 /W4 /WX 通过，archive.cpp /W4 的三条已有警告已单独保留。

真实 Electron、ArchiveService 和 helper 完成 10 个百万条目流程，始终最多 200 行；目录导航、搜索、翻页、实际停止和重新打开通过。此次取消耗时 50.3 ms，16 ms 界面计时器的最大间隔 44.6 ms，最多 4149 个 DOM 节点。主进程和渲染进程各自峰值工作集约 138.2 / 196.4 MiB；没有旧版整应用对照，不将原生 helper 的下降比例推广到整应用。常规界面回归另通过；Explorer 拖出在该回归中有模拟，百万基准没有执行 Explorer 或解压。

## 重现与范围

`npm run bench:archive-browser` 使用 Windows Python 标准库生成并复用本机样本、记录当前原生 helper；`npm run bench:archive-browser-ui` 在同一数据上测真实桌面。源码：[原生基准](../../../tests/archive-browser-benchmark.py)、[桌面基准](../../../tests/archive-browser-benchmark-ui.cjs)。先保存基线 helper 及配套 DLL，再构建优化版；用 `--label baseline --helper <旧版helper>` 与 `--label optimized --compare work/current/archive-browser-perf/baseline.json` 做同数据对照。两轮不得并行运行或夹入其他重负载，界面基准使用隔离 profile，结束后回收。

完整过程数据位于 `work/current/archive-browser-perf/`，精选证据位于 `verification/archive-browser-perf/`。大型样本可由脚本重新生成，不属于发布内容。每场景只有两次观察，不作统计显著性结论。十万小文件、超大固实包、慢盘/网络盘、系统冷缓存、安装版及权限/断电矩阵继续按原计划验收。
