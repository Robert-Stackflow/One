# 归档 7Z 分卷诊断记录

2026-10-10，开发版新增 7Z 不完整数据与不可读分卷提示。此前缺少中间卷、末卷、文件被截断或中间卷被独占时，共用“检查格式、分卷或密码”的错误；现在浏览、校验和解压会提供更明确的原因。整体归档计划仍有其他兼容、性能及安装版验收范围。

## 实现与边界

`native/archive/sevenzip.cpp` 在 SDK 的 `Open` 返回后、关闭处理器前读取 `kpidErrorFlags`，只在 `UnexpectedEnd` 标志存在时报告不完整数据；内存预算错误仍优先处理。读取失败时保留系统错误及停止读取的分卷位置，主进程转换为中文提示。

- 单卷：提示文件不完整或被截断。
- 分卷：提示最后读取卷与下一卷的文件名。下一卷不存在也可能是前一卷被截断，提示保留这一边界，不断言某个文件必然缺失。
- 下一卷存在但被独占或无法打开：提示无法读取该卷，并建议检查占用与权限。

识别依据来自仓库固定的 7-Zip 26.04 源码：`CPP/7zip/Archive/7z/7zIn.cpp` 的 `ReadDatabase` 在下一头部范围超出输入长度时设置 `UnexpectedEnd`；`7zHandler.cpp` 的 `GetArchiveProperty` 暴露该标志。错误密码、头部损坏仍可能无法彼此区分，继续使用原有诊断。无法识别的极短文件和其他损坏方式不保证能定位卷边界。

## 验证

入口：`npm run test:archive-seven-diagnostics`，需要外部 `7z`；也可传 `--writer`、`--native` 和新的 `--report` 路径。此入口未加入要求离线运行的默认测试。

使用独立 7-Zip 25.01 写入普通、数据加密和头部加密三份 Copy 方法归档，各包含确定性 256 KiB 数据，再按 32 KiB 切为分卷；外部写入器先验证单卷及分卷均完整。中文归档名覆盖错误文本中的 UTF-8 文件名。

- 三种加密各验证缺中间卷、缺末卷、截断末卷及截断单卷：共 12 个损坏输入，36 次原生浏览/校验/解压均失败、无成功结果及输出目录；12 次真实服务调用验证中文提示。
- 成功单卷及分卷解压共六次，逐次核对完整输出 SHA-256；恢复损坏卷后核对原始文件哈希。
- 错误密码、头部加密未提供密码、损坏起始头部作为对照，均未误报不完整数据。
- 用真实 Windows 独占读句柄锁住第三卷，原生与服务均指向该文件；释放后校验恢复成功。
- 外部写入器生成的 32 字节空归档，以及附加 128 字节尾部的空归档均可读取。

旧版本冻结副本完成相同的损坏输入和独占卷对照，证实原有错误不含新增定位信息。新版本另通过密码、固实、格式、空间、RAR 及失败目录回收六组现有回归和类型检查。结构化结果见 [测量证据](measurements/archive-seven-diagnostics.json)。
