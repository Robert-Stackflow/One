# One 压缩与解压实现计划

> 编写于 2026-10-08。本文是分阶段实现方案；ZIP、7Z、TAR、TAR.GZ/TGZ、TAR.XZ/TXZ、GZ 和 XZ 的创建、浏览、校验、解压，以及 RAR 的只读浏览、校验、解压已落地，其余能力继续按阶段推进。需求来源：创建压缩包、多格式解压、双击智能解压、右键操作、分卷、加密、浏览与拖出、包内修改、校验与防护、性能、旧 ZIP 文件名编码、文件管理和批量命令行。竞品行为参见 [Bandizip 功能与设置调研](../research/Bandizip功能与设置调研.md)。

### 当前进度

- 2026-10-09：分卷修改完成原生重写准备阶段，尚未开放分卷包的界面/CLI 原位保存。内部 `update-prepare` 在整组源卷修订和只读锁保护下，先完整校验原包（包括要删除的项），按同一修改计划重写为同格式的单卷暂存 ZIP/7Z，再核对完整目录、加密状态及内容；ZIP 另核对备注，7Z 保留原有加密头语义。该单卷文件是整组保存流程的中间产物，不是将分卷修改替换成另存为单卷的产品方案；准备完成不请求提交握手，不替换/删除任何原卷。
- 分卷 ZIP 保留项复制原压缩数据；7Z 重命名可复用 packed data，固实块内的内容变更交给原引擎重写。7Z 空间预检改为整组卷大小求和，并防止大小/条目开销相加溢出；追加内容拒绝本压缩包的所有卷及其硬链接别名，递归添加不做卷数与文件数的双重遍历。完成前重新打开源族并核对修订，缺失、替换或损坏的源卷不接受为有效原件。
- 准备结果仅返回已观察到的卷尺寸：7Z 使用首卷尺寸，ZIP 使用终结 `.zip` 以外卷的最大物理尺寸。ZIP 不记录创建时配置的分卷上限，记录边界可能让实际卷稍小，不能把观察值称为原始配置。下一步仍需按分卷格式重新生成卷组、处理增减卷和旧尾卷、原件与暂存的身份核对、持久化组事务及可重试恢复，再接入界面/CLI；既有单卷修改和分卷只读限制继续生效。

- 2026-10-09：补齐显式恢复资料清理入口。检查后区分“已确认发布完成的原文件副本”和“已还原后隔离的新内容”，清理前永久删除确认，复用归档队列、跨进程资源预算、所属窗口取消、日志与持久任务历史。已完成发布须核对目标仍为原发布文件；未完成发布须核对所有原文件已还原、新增目标已移出且没有未恢复副本，不能跳过还原直接清理。
- 原生清理独立验证完整版本 2 清单、链式校验、路径范围和目录身份，先核对全计划，再逐文件复查；每次删除持有已核对目标及副本的句柄，阻止目标在核对与删除之间被写入或替换。只删除清单对应的 `.original`/`.displaced` 文件，再删除清单和空恢复目录；不递归删除，不删除目标目录，未知文件/子目录/链接均拒绝处理。文件变化、占用、损坏清单或部分还原时停止，剩余资料保留；已删除的副本不可撤销。
- 支持副本逐项删除、清单删除、目录删除后的进程异常退出重试；缺失目录仅移除独立索引，缺失清单且真正为空时可完成最后的目录清理，有未知内容则保留。只在原生清理成功且确认恢复目录消失后移除索引；失败、取消或进程退出保留索引。只读检查新增“仅剩空目录”状态，清理完成显示实际本次删除数量。

- 2026-10-09：接通异常退出后的显式原文件还原。恢复资料检查结果中，未确认完成发布或已有回滚记录的任务提供“还原原文件”；完整发布的任务拒绝按失败任务回滚；副本清理见后续清理阶段。还原复用归档资源队列、同用户跨进程预算、停止、窗口所属关系、日志和任务历史，服务先核对独立索引，原生进程再独立验证版本 2 清单的规范 JSON、序号、链式 CRC、完整计划、状态顺序及路径/目录身份。清单与所有已检查的目标祖先通过句柄锁定；文件须为无重解析点、无额外硬链接的普通文件。
- 还原先检查完整计划，逐文件再核对卷/文件编号、大小和最后写入时间。未完成发布的原文件副本放回目标；已发布的新内容移入同一恢复目录的 `<index>.displaced`，所有移动均通过已核对的文件句柄且不覆盖已有位置。副本缺失、身份变化、占用、目录联接或确认后出现的新目标均停止，保留已完成部分；后续调用根据当前文件位置继续，支持在每次移动后进程异常退出再重试。原发布清单保持不变，不以第二份可能截断的追加日志作为重试前提；检查界面仍显示原发布记录，完成反馈明确区分实际还原结果。文件指纹属于元数据核对，不是内容哈希，不能证明刻意保留身份/大小/时间的内容篡改不存在。
- `tests/archive-restore.cjs` 覆盖真实发布异常退出、暂存已回收、逐次还原中再次硬退出与重启重试、重复执行、新内容保留、已完成发布拒绝回滚、用户后续修改/副本缺失或改动、硬链接/联接/类型替换、伪造/损坏/截断清单、同一资料独占操作、取消及确认后的修改；服务回归覆盖资源调度入口、同 ID 并发拒绝、跨窗口取消隔离、恢复任务历史重载及恢复进程退出后索引保留。还原不删除目录、隔离的新内容或原清单，该还原阶段未包含资料清理；显式清理已在后续阶段补齐，自动清理不启用，断电持久性仍未证明。界面交互待用户验收。

- 2026-10-09：接入持久化恢复索引与只读检查入口。解压至此先在 profile/tasks/archive-recovery 中写入独立任务记录并同步，再用硬链接无覆盖发布完整索引，之后才允许原生发布器修改目标；记录写入失败则停止发布，注册中途的半份内容不暴露到列表。正常发布或完整回滚已移除恢复目录时清除索引；异常保留时索引不随任务历史淘汰。GUI/CLI 共用 profile 下的索引位置，重启可查；最多读取 1024 条目录记录、每页 50 条，超量仍允许检查/移除可见记录并刷新，不自动删除其余资料。不支持索引硬链接发布的文件系统会在目标写入前失败，不降级为可能暴露部分记录的复制。
- 恢复检查按 64 KiB 流式读取版本 2 清单，验证完整头部、计划路径、递增编号、链式 CRC、发布/回滚顺序和目录身份，单条 512 KiB、总计 512 MiB，保存 100 万项标志及最多 30 个路径样本。Windows 的路径 lstat 卷编号可能为 0，目录身份改用异步 Win32 句柄查询，并拒绝 reparse point；不能混用 lstat/fstat 的 dev 判断同一文件已变。检查前后再比对资料身份/大小/时间；所有操作只读，不以外部清单内容授权覆盖或清理。每次最多两项检查，按窗口所属关系取消，窗口关闭和服务停止会终止读取并等待释放句柄。
- 页面增加“恢复资料”对话框，支持分页、检查结果、显式查看目录、停止检查和经确认仅移除索引；未知/损坏记录参与管理，另一个存活实例可能持有的记录阻止检查/移除。tests/archive-recovery.cjs 覆盖真实原生进程硬退出、服务重启保留、同步写入时不可见、不覆盖已有 ID、10,000 项流式检查与有界样本、实际读取中取消、跨窗口取消隔离、服务停止、他进程存活、损坏/伪造/截断/超限、目录替换/联接、只读与索引移除边界及登记失败不改目标；原事务发布和清单回归通过。此阶段并未实现文件还原或副本清理，也未证明硬件断电持久性；下一步仍需原生独占锁、当前文件身份核对、用户后续修改保护和可重复执行的显式恢复协议。

- 2026-10-09：查看本机 Bandizip 的默认 ICO 资源后，为 One 独立绘制 46 个文件图标：覆盖用户截图中全部格式，另含通用归档和 R00。未接入的 ZIPX、ALZ、EGG、CAB、BH、ARJ、LHA/LZH、PMA、ACE、ARC、AES、ZPAQ、ZSTD、BR、其他 Unix 格式、应用包和光盘镜像仅准备图标，不注册为可用格式；当前实际关联仍是 ZIP、7Z、RAR、R00、TAR、TGZ、GZ、TXZ、XZ。使用纸张、拉链和 One 标记，按格式区分标签/颜色；每个 ICO 含 16、20、24、32、40、48、64、96、128、256 像素，最小尺寸采用单独绘制的像素标签。各格式使用独立 ProgID/DefaultIcon，ICO 解包为真实文件供 Windows Shell 读取；构建复制资源，复用构建打包时检查源文件哈希。旧版共用 ProgID 保留可用，设置中可更新注册，不改动 Windows UserChoice 或其他程序的默认关联。小尺寸使用兼容传统读取器的 32 位 BGRA DIB/AND mask，256 像素使用 PNG。验证覆盖 ICO/DIB/PNG 帧结构与 CRC、Windows 原生 LoadImage 读取全部尺寸、实际安装路径映射、隔离注册表中的迁移/同路径更新/异路径升级/卸载及资源缺失保护；尚未打包或验收正式安装版的 Explorer 显示。

- 2026-10-09：解压至此的恢复清单升级为版本 2，记录目标/暂存/恢复目录身份、完整写入计划、原文件与暂存文件指纹、新建目录身份和实际发布记录。每行有递增序号及链式 CRC32，限制单条 512 KiB、累计 512 MiB。完整计划先落盘，再允许写入目标；全部发布后先持久化 `committed` 标记，之后才删除原文件副本。普通异常仍按文件身份回滚；完整回滚也先记录 `rolled-back` 再清理清单。记录按 64 KiB 合并写入，常规发布期间每 250 ms 检查刷盘，不对每个小文件同步刷盘，关键决策使用独立持久化屏障。异常退出可能丢失末尾尚未刷盘的进度记录；恢复判断必须结合持久化计划与当前文件身份，不能将没有逐项发布记录等同于未执行；没有可验证身份的新目录不得自动删除。
- `tests/archive-journal.cjs` 通过直接终止原生进程（绕过析构和异常回滚）验证：完整计划后、备份原文件后、安装新文件后、完成标记后、清理部分副本后的清单与原件状态；覆盖提交记录写入失败时恢复原件、非测试环境忽略故障注入、服务报告准确恢复目录且不删除恢复副本。链式 CRC 用于检测截断、顺序或意外损坏，不是身份认证或内容哈希。上述证明的是本机进程异常退出边界，不证明所有文件系统/硬件断电行为。重启后的清单检查、恢复界面与显式恢复操作仍待接入；不得仅凭 `committed` 字段或未经验证的外部清单自动删除或覆盖文件。

- 2026-10-09：补齐 RAR4 备注读取。现有 7-Zip 容器不暴露该属性，新增独立的有界头部读取器，识别 RAR3/4 的 CMT 服务记录和早期内嵌 0x75 备注；压缩数据复用原 DLL 的 RAR 解码器，不添加依赖、不落盘提取备注。校验头部 CRC、声明长度及数据 CRC；支持 UTF-16、ANSI/OEM 文本，拒绝异常 Unicode/NUL、超限与损坏数据。单条备注的压缩/展开大小均限 256 KiB，SFX 签名扫描限 8 MiB，头部扫描限 100 万条及 64 MiB；普通 RAR 从首部直接开始，不为查找签名读取整个文件。浏览、搜索、快速预览复用列表结果，完整性测试补查备注。依据 [RAR 原作者的备注读取实现](https://github.com/pmachapman/unrar/blob/master/arccmt.cpp)、[头部定义](https://github.com/pmachapman/unrar/blob/master/headers.hpp) 和 [7-Zip RAR 编解码器接口](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Compress/RarCodecsRegister.cpp)。
- `tests/archive-rar-comments.cjs` 使用真实 RAR3 压缩 CMT 的小型编码样本，以及生成的 UTF-16/ANSI/OEM、旧式内嵌、空备注、文件前后服务记录，验证列表/搜索/预览、CRC、解压内容和原件不变；覆盖损坏头部/压缩流、截断、长度不符、超限和无效文本。加密头中的 RAR4 备注、单独加密/分割的 CMT、旧式 RAR1/2 压缩备注的实际样本兼容性仍未完成，不将支持 RAR3/4 压缩备注等同于所有历史版本通过。

## 1. 目标、术语与交付边界

文件关联采用 Windows 的 [OpenWithProgids 注册](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-include-an-application-on-the-open-with-dialog-box)、[RegisteredApplications 与 Capabilities](https://learn.microsoft.com/en-us/windows/win32/shell/default-programs)，应用名保持一致；通过 [默认应用设置入口](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-apps-settings)交给用户选择，不修改受保护的 UserChoice。

- 在侧边栏“文件”分组末尾提供独立的“压缩与解压”入口，让文件管理页、拖拽、预览、资源管理器右键和命令行都使用**同一套归档任务引擎**。不把 ZIP 预览器误用作完整解压器。
- “加压到同名文件夹”按上下文理解为“**解压到同名文件夹**”。“双击智能解压”指用户把压缩格式关联到 One 后，在资源管理器双击压缩文件，默认执行智能解压；设置中可改为“打开并浏览”，以免接管文件关联后失去查看入口。One 内文件列表双击遵循相同偏好，列表中仍保留明确的“浏览压缩包”动作。
- **格式能力分开标记**：可浏览、可解压、可创建、可编辑、可分卷、可加密；不能因“可打开 RAR”而暗示能创建或修改 RAR。格式不足时明确报“不支持此操作”，不偷偷转换格式。
- 第一条可用链路优先覆盖 ZIP/ZIP64、7Z、RAR/RAR5（RAR 仅浏览、解压、测试）。TAR、TAR.GZ、GZ、XZ、ISO、CAB 等列为扩展验证矩阵；具体可用操作按引擎能力与互操作测试启用，不用扩展名推断能力。
- 解压不是杀毒软件。默认提供路径防护、完整性测试和来源标记；接入 Windows 反恶意软件接口后也只显示“扫描结果”，不宣称文件绝对安全。

### 建议的功能矩阵

| 格式 | 浏览/选择提取 | 创建 | 原位修改 | 分卷 | 密码/加密 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| ZIP/ZIP64 | 必做 | 必做 | 必做，事务式重写 | 必做，标准多盘 ZIP | 读取传统加密与 WinZip AES；创建默认 AES-256 | ZIP 包备注、条目备注、旧编码处理均需覆盖。 |
| 7Z | 必做 | 必做 | 二期，以重写归档实现 | 必做，`.7z.001` 系列 | AES-256，支持加密文件名 | 固实压缩随机提取可能需要解码整个固实块。 |
| RAR/RAR5 | 必做 | 不做 | 不做 | 读取常见 `.partN.rar`，需实测 | 有密码时可解密 | RAR 压缩不是本计划目标；包备注以引擎实测能力为准。 |
| TAR/TGZ/GZ/XZ | 常用组合必做 | TAR/TGZ/GZ/XZ 分阶段启用 | 不做 | 不承诺原生分卷 | 通常无容器级密码 | 需区别单流压缩与多文件归档。 |
| ISO/CAB/其他 | 按通过测试的引擎能力开放只读 | 不承诺 | 不做 | 不承诺 | 依格式 | 错误提示要给出“格式识别成功但方法不支持”。 |

7Z 的 AES-256、Unicode 文件名和固实压缩是格式本身的公开能力；RAR 只做读取也符合开源引擎的通常边界。[7z 格式说明](https://www.7-zip.org/7z.html)、[7-Zip 官方下载/源码](https://www.7-zip.org/download.html)。

| 库/引擎 | 确认的优势 | 对本需求的缺口 | 建议用途 |
| --- | --- | --- | --- |
| [minizip-ng](https://github.com/zlib-ng/minizip-ng/blob/develop/README.md) | zlib 许可；ZIP64、WinZip AES、流式读写、拆分磁盘、UTF-8 和 CP437/932/936/950、增删 ZIP 条目。 | 只处理 ZIP 系列；编辑和标准分卷的边界仍要做互操作测试。 | **ZIP 主引擎**，优先支持旧编码、备注、分卷和事务修改。 |

| [libzip](https://libzip.org/documentation/libzip/) | BSD 许可、ZIP 的创建/编辑/备注/AES API；修改时先写临时文件再替换原件。 | 官方错误表列出“不支持多盘 ZIP”，无法单独满足本次分卷要求。 | ZIP 主引擎回退方案；若 minizip-ng 原位修改、备注处理未通过验证，再评估用它承担非分卷 ZIP 修改。 |
| 现有 `JSZip` / `yauzl` | 已用于轻量预览和 Office 容器读取。 | 不覆盖 RAR/7Z/标准分卷及完整加密、修改工作流；大任务若跑在渲染侧会放大内存和卡顿。 | 保持现有预览用途，**不作为归档主引擎**。 |

许可与分发：7-Zip 的官方[许可文本](https://www.7-zip.org/license.txt)指出主体为 LGPL，部分 RAR 解压代码带 unRAR 限制；二进制再分发需保留相关许可证信息。设计为**独立原生进程动态加载原版 7z.dll**，固定版本、记录来源与 SHA-256，并更新 `THIRD_PARTY_NOTICES.txt` 与源码获取说明。minizip-ng 及启用的 zlib/zstd 等依赖也逐项核对许可证。此处是工程合规方案，合并依赖前还要检查所选版本的实际 LICENSE 和构建选项。

### 先做四个短原型，再锁定依赖

1. minizip-ng：创建大于 4 GB 的 ZIP64、标准 `.z01/.zip` 分卷、AES-256、中文/日文旧编码、包备注和单条目备注；用 Bandizip、7-Zip 交叉读写高级特性，Windows 文件管理器只验证其实际支持的普通 ZIP 操作。
2. 7z.dll：在 One 原生进程中列出、选取提取与测试 7Z/RAR5、加密 7Z、`.7z.001` 和 `.partN.rar`；验证非 ASCII 路径、Unicode 名称及错误/密码回调。
3. 结构化元数据：确认 ZIP/RAR 备注能从归档属性读取；若 RAR 备注不可得，界面显示“此格式或文件未提供可读取的备注”，不能解析脆弱的本地化命令行文本冒充支持。
4. 包体积与冷启动：记录两套原生库、可选压缩算法、辅助进程对安装器增加的大小和首次打开耗时；超预算就精简编译特性，不通过删安全检查换体积。

原型未通过时，文档中的对应格子维持“待实现”，并在实现前调整引擎或缩小明确的格式范围；不先做“全格式支持”营销承诺。

## 4. 执行架构与协议

```text
文件管理/压缩页/双击关联/右键菜单/命令行
              ↓ 统一的已校验任务请求
Electron 主进程 ArchiveService ── 任务状态/取消/冲突决策/进度
              ↓ 有长度限制的 UTF-8 消息，不含任意 shell 命令
独立 One.Archive.exe ── minizip-ng ZIP ── 7z.dll 多格式
              ↓ 受控输入流和输出句柄
预检清单 → 暂存目录/文件 → 校验/可选扫描 → 提交到目标
```

- 原生进程按**每个任务独立启动**。主进程只接受操作类型枚举，不把渲染进程给出的任意参数拼成命令行。内部协议用长度前缀 JSON 消息承载 `start`、`progress`、`password-required`、`conflict`、`cancel`、`result`；大清单按页返回，文件内容不经过 IPC。密码经私有管道传递，不进 argv、日志、最近任务或备份设置。
- `ArchiveService` 持有全局任务 ID、源文件稳定标识、目标目录、阶段、取消令牌和清理凭据。页面切换、主窗口缩到托盘不终止任务；真正退出时等待安全提交结束或显式取消并清理。若应用是管理员身份启动，优先用现有普通权限启动器拉起非提权归档进程，防止 Explorer/拖拽跨完整性级别失效；写保护目录时才走受控提权路径。
- 任务阶段：`识别 → 读取目录/分卷 → 预检 → 排队 → 读写 → 校验 → 可选扫描 → 提交 → 完成/取消/失败`。把“已处理输入字节”和“已写出字节”分开报告；未知总量用阶段式进度，不造假百分比。每 100–200 ms 最多推一次 UI 进度，避免数十万小文件刷屏。
- `list` 返回分页条目：稳定条目 ID、原始路径、解码显示名、类型、压缩/展开大小、时间、加密标记、校验信息和警告。前端虚拟列表按需加载；双击目录仅展开树节点，不一次把百万条条目塞进渲染进程。
- 设计一个内部 `ArchiveBackend`：`probe/open/list/extractSelected/create/update/test/getComment`。每种能力按“格式 × 操作”运行时宣告。ZIP 与非 ZIP 引擎的密码、进度、错误码统一映射，但不掩盖格式特有的选项。

### 命令行与批量任务

面向用户的入口为独立控制台程序 `One.Cli.exe archive list/create/extract/test/update/batch`；`One.Archive.exe` 保持私有引擎协议，不直接暴露给用户。命令行复用 ArchiveService 和原生引擎，运行于独立 Node 模式进程，不加载 GUI、托盘、全局 hook 或单实例锁。`--json` 使用 JSONL，默认输出终端文字；输入的文件名不经 shell。已支持 `--output`、`--format`、`--volume-size`、`--encoding`、`--select`、`--conflict`、`--password-stdin`、`--changes`、`--jobs`、`--progress`。压缩等级 `--level`、压缩线程 `--threads` 与内存上限 `--memory-mib` 已实现；扫描策略 `--scan`/`--no-scan` 已实现，默认关闭。批次逐个汇总成功、跳过、失败，提供明确退出码；密码只经 stdin 和私有引擎管道。完整契约见 [压缩命令行](../user-guide/压缩命令行.md)。

## 5. 关键交互与文件管理

1. **创建压缩包**：选文件/文件夹或拖入 → 展示目标路径、格式 ZIP/7Z/TAR、压缩级别、是否加密与分卷大小 → 估算输入量和可用空间 → 后台开始。默认 ZIP 使用 Deflate/UTF-8；密码新建默认 AES-256，不把传统 ZIP 加密作为推荐选项。
2. **打开与智能解压**：关联格式双击按用户偏好“智能解压”或“打开浏览”。智能解压先读完整顶层结构：若仅一个文件或全部在同一顶层目录，则解压到当前目录；否则新建以压缩包命名的目录。同名目录另取序号，**不直接覆盖**。此规则借鉴 [Bandizip 智能解压说明](https://cn.bandisoft.com/bandizip/help/auto_dest/)。
3. **明确的解压菜单**：“解压至此”解到当前目录；“解压到〈包名〉”始终创建目录；“智能解压”自动选；“选择位置…”打开目标选择器。资源管理器的压缩包右键、One 文件列表右键和归档页共用同一任务参数。多选压缩包时逐包智能解压并显示聚合进度。
4. **浏览与选取提取**：显示路径树、列表、搜索、压缩率、加密标记、ZIP/RAR 备注（能读才展示）；条目多选后提取到指定目录或拖出到 Explorer。拖出要产生 Windows 可识别的文件拖放，不只在 One 内触发 HTML DragEvent；临时提取文件按引用计数和 TTL 清理，用户取消拖放时也清理。
5. **修改归档**：ZIP 支持添加、删除、重命名、新建目录和替换。开始前展示变更预览，重写到同卷临时文件，完整验证后替换原文件；失败保留原件。7Z 修改列二期，只有测试证明更新可用时开放；RAR 只读。包内文件“打开编辑并保存”需明确使用临时文件且写回前检查原包是否已变更。
6. **设置**：设置页新增“压缩与解压”，只放长期偏好：双击动作、默认压缩格式、默认压缩级别、解压同名冲突策略、解压后打开目录、来源标记传递、可选病毒扫描、资源上限、右键菜单开关与文件关联。每次任务的密码、目标路径、分卷大小留在操作对话框；高级选项默认折叠，按格式显隐。

## 6. 安全与可靠性设计

- **预检路径**：使用归档内原始字节名与解码名同时校验。拒绝绝对路径、盘符、UNC、`..` 越界、`\\?\` 设备前缀、NUL/控制字符、NTFS ADS 的冒号、Windows 保留设备名、末尾空格/句点；对规范化后重名、大小写折叠重名、目录/文件重叠报冲突。默认不创建包内符号链接、junction 或其他 reparse point；写入时逐级检查并持有目标目录句柄，阻止预检后目录被替换成链接的竞争条件。未来放开包内链接时必须证明最终写入位置始终在目标根目录内。
- **预检资源预算**：默认对极端条目数、声明展开量、异常压缩比和嵌套归档显示风险并要求用户显式继续；后台写入仍按**实际**展开字节、时间和目标磁盘余量限额，防止伪造元数据绕过。大文件正常工作不因一个低的固定阈值被无条件拒绝；预算可按用户显式选择调整。
- **受控提交**：新建压缩包先写同卷临时文件，再校验并重命名；智能解压到新文件夹先写随机暂存目录，再整体提交。解压到现有目录无法保证全量原子提交，因此逐项记录已创建/已替换内容，冲突时先询问，取消时只回滚本次创建且仍存在的文件，不删除用户原有文件。覆盖旧文件先单独备份或采用安全替换。
- **校验**：测试操作完整读取条目并比较格式能提供的 CRC/散列；“测试通过”只表示所测数据与容器校验一致，没有校验字段的格式只报告可读性。密码错误、缺少卷、CRC 失败、部分失败分别显示。创建后可选自动测试，修改后强制测试新包。
- **恶意软件扫描**：Windows [AMSI](https://learn.microsoft.com/en-us/windows/win32/amsi/antimalware-scan-interface-portal) 支持应用向本机反恶意软件提供者提交内容；小文件可用 `AmsiScanBuffer`，大文件应评估流式 `IAmsiStream`，不把整包载入内存。没有可用提供者、扫描失败或超限时显示“未完成扫描”，不能显示“安全”。扫描应是可关闭的可选步骤，不阻塞纯列表浏览。
- **来源标记**：如果输入压缩包带 `Zone.Identifier`，对成功落盘的相关文件按 Windows 来源标记规则传递，保留系统后续警告能力；不为了提速默默清除标记。参考 [微软文件命名流文档](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams)；修改原包使用 [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)，保留原件中替换文件没有的命名流。
- **不可信输入隔离**：原生引擎不得以管理员身份解析互联网压缩包；原生进程只接收确定的源/目标句柄、受限任务参数和预算，不能执行包内文件。解析崩溃、卡死或用户取消时终止该任务进程并按所有权标记清理暂存。日志只记操作、耗时、错误码和脱敏路径，不记密码、条目正文或敏感完整路径。

## 8. 分阶段实施与完成标准

### 阶段 1：ZIP 可用闭环

- 实现 ZIP 浏览、创建、选择解压、智能解压、同名目录、拖入、标准分卷、密码、ZIP64、手动代码页、CRC 测试、路径预检及原生任务进度。

- **完成标准**：断电模拟/进程崩溃/空间不足/目标占用时原包不损坏；恶意包不越界写入；打包后的许可说明和安全回归通过。

### 当前条目拖出进度（2026-10-09，开发版）

- 列表支持拖出单项或勾选的多项，跨页勾选会保留；选择目录会包含子项并折叠重复选择。共同父目录会从输出名称中去除，必要的父目录描述自动补齐；有未保存修改时提示先保存或放弃。
- [原生拖出模块](../../native/archive/drag.cpp)提供 Windows `FileGroupDescriptorW` / `FileContents`、只读 `IStream` 和 `IDataObjectAsyncCapability`，辅助进程执行 OLE 拖放及按需解压。主进程传入实际源窗口句柄，辅助线程临时共享源窗口输入队列，不主动激活其他窗口。源包锁定并核对列表修订；密码和最多 10,000 个勾选索引通过私有标准输入传输。目录展开最多 65,536 个描述项，相对名称受 Windows 文件描述 260 字符限制，超出提示普通解压。
- 解压复用现有路径、链接、重复名、磁盘余量、CRC/声明大小检查；临时解出内容留在独立 cache 子目录。开始 OLE 后不允许主进程强杀正常传输，退出等待接收端结束异步操作并释放所有内容流；复制、密码错误和取消后主进程回收暂存。ZIP 和 7-Zip 提取进度节流至约 100 ms；保留密码首尾空格。
- [协议测试](../../tests/archive-drag.cjs)覆盖多选目录结构、中文、空文件/目录、加密 ZIP/7Z、TAR/GZ/XZ 与复合 TAR.GZ/TAR.XZ、大小/内容哈希、克隆流、跨 STA 的真实 COM 封送、过期修订、危险路径、取消、成功/密码失败后的清理，以及退出等待。 [页面测试](../../tests/archive-drag-ui.cjs)覆盖跨页多选、单项、IPC 修订/密码、忙碌保护、取消和未保存修改阻止。测试中使用内部模拟接收端，不打开 Explorer。
- 拖出暂存采用生成任务标记与原生占用锁：辅助进程整个传输期间禁止删除/改名锁文件；应用启动、拖出前及退出时只回收带有效标记、已超过 24 小时且能取得清理锁的暂存。正常任务立即回收，退出不再递归删除整个共享缓存。损坏标记、未知目录和活跃锁保留，清理异常写入运行日志。[缓存测试](../../tests/archive-drag-cache.cjs)验证真实辅助进程持锁时的新实例退出保护、辅助进程终止后的 TTL、清理中断恢复、未知目录及 junction 边界。
