# One 压缩与解压实现与验收设计

适用于当前开发版。功能支持及操作以[用户指南](../user-guide/压缩与解压.md)为准；当前状态与剩余工作由[TODO 的 ARCH 系列](TODO.md)统一维护。原始方案、逐次实施和阶段验证已归入[开发记录](../history/projects/压缩与解压阶段设计与开发记录.md)，不作为当前能力声明。

## 范围与引擎

已有 ZIP、7Z、TAR 及 GZ/XZ 相关操作；RAR、ZIPX、CAB、BZ2/ZSTD、LHA/LZH、ISO/WIM、JAR/APK、ALZ 及 TAR.BZ2/TAR.ZST 只读。创建、浏览、测试、解压、加密、分卷和修改矩阵及限制见用户指南；读取支持不自动开放创建或编辑。未接入的格式先核对许可、上游源码能力、产品入口和真实样本，选型依据见[原生引擎调研](../research/归档功能缺口与原生引擎调研.md)。

首批格式读取复用随包 7-Zip 26.04 DLL 的实际处理器（现由固定源码及最小密码编码补丁构建），ZIPX/JAR/APK 使用其 ZIP 处理器，已有 `.zip` 继续使用 minizip。服务、预览、搜索打开、文件菜单与 CLI 共用扩展名识别；Explorer 原生菜单及关联注册维护对应格式。新格式只读且限单卷，打开时检查引擎报告的头部错误，不接受不完整分卷目录。 ALZ 使用独立有界目录解析器与修改后的 bzip2 1.0.8 DLZ 解码；不使用旧 UnAlz 的文件写入和目录解析。三种方法均核对外层 CRC32、精确展开长度和累计字节/时间预算，沿用暂存、发布、来源标记和扫描流程。CP949 可显式选择；ALZ 自动默认 CP949，密码与文件名选项一致。ISO 尝试 UDF 后回退 ISO9660，具体版本仍须样本验收。

单流不提供展开大小时，协议返回 `sizeKnown:false`，界面显示未知大小。写入不以零作为大小上限，仍逐块执行实际展开量、时间和磁盘余量预算；已知大小继续检查声明与实际一致。未知大小的独立流需先解压再拖出；复合 TAR 准备完成后按内部条目的已知大小操作。

## 外部编辑回写

从可编辑 ZIP/7Z 选中唯一文件，按原名提取独立副本；文本/源码/脚本进入文本编辑器，未知类型显式选择程序。目录观察兼容原子替换保存，返回前台补查。原生观察器跟踪能够获取的进程句柄，复用窗口或转交进程时保守提示；退出 One 释放观察器并保留副本。

确认写回校验文件 SHA-256 和源修订，使用独立快照；事务返回受校验的最终修订，使同一会话能连续编辑。原包变化时停止旧版本保存，显式核对原条目未变、内容冲突、删除/改名或重复同名；确认当前原包后仍需再次批准写回。

写前登记快照意图，持久记录不确定阶段；中断后比较批准内容与原包条目，再确认结果，不自动重放。已退休快照及核对暂存按记录回收；未知文件、编辑器备份、损坏记录和链接替换保留。独立另存拒绝覆盖已有文件并保留来源标记，结束编辑前要求关闭文件窗口。

实现入口：[archive-edit-sessions.ts](../../src/main/archive-edit-sessions.ts)、[archive-edit-launch.ts](../../src/main/archive-edit-launch.ts)。单文件 256 MiB、最多 16 份会话，密码不写入记录。真实编辑器、权限与安装版的剩余验收见 ARCH-EDIT。

## 事务、恢复与防护

修改先形成明确变更与预览，保存前校验源修订；进入最终提交前完成取消握手。解压、分卷生成、暂存交接、正式发布及回滚保留各自的记录与所有权边界。

单卷 ZIP/7Z 原子替换兼容下载来源标记及其他 NTFS 命名数据流。[Windows ReplaceFile](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) 会合并原文件属性和数据流；实测合并会改变替换文件的修改时间。含命名流时，保存前记录暂存内容指纹，替换后在读锁下同时核对文件身份、大小与内容；不将合法时间变化误报为冲突，也不放过同大小、同时间的内容篡改。普通文件继续使用修订检查，避免额外全文件读取。失败保留原包恢复副本；验证入口为 `test:archive-ads-update`。

分卷来源记录与发布清单完成可靠交接后才允许移动原卷。中断检查、还原和清理使用重新核对的记录、文件身份及确认令牌；同内容复制件、无记录暂存、未知文件及损坏资料不自动获得删除权限。实际恢复入口在[用户指南](../user-guide/压缩与解压.md)维护。

路径与链接、重复条目、目标冲突、提取空间、解压预算、来源标记和可选扫描沿用统一检查。主进程结果也必须校验；密码编码与文件名编码分别处理，不在任务历史或普通设置中保存秘密。

## ZIPX 密码编码

7-Zip ZIP 处理器原先固定用系统 ACP 转换密码，文件名 `cp` 属性不影响密码。One 为它加入独立的 `pwcp` 属性，接通 UTF-8、系统编码及 CP437/932/936/949/950；不借助有损转换或修改进程区域设置。原生入口先验证可精确表示，RAR/7Z 等处理器保持原密码逻辑。源码、哈希、补丁、许可及重建入口见 `vendor/archive/7zip/` 和 `scripts/build-sevenzip.mjs`；打包配置携带完整源码胶囊及补丁。

`test:archive-zipx-password` 的 430 项检查独立重加密十份编解码/加密样本（含三份保留外部 ZSTD 方法 93 流的独立 AES128/256 AE-1/AE-2 包），覆盖多语言、emoji、空格、错误密码/编码、解压哈希、拖出、CLI（含独立可执行文件）、预览和 JAR/APK；桌面流程由 `test:archive-zipx-password-ui` 验证。精选证据见 `verification/archive-zipx-password/latest.json`。

## 验证入口

`test:archive-egg-reference` 固定 MIT 参考源码并离线构建独立验证程序，实际解码并验证 CRC 的 22 个 EGG 数据集；它用于后续 C++ 实现的比对，不表示产品已支持 EGG。`test:archive-egg-azo` 已验证 C++ AZO 解码模块：5 份独立输出哈希、内层多块、截断、内存限制和取消共 377 项检查；`test:archive-egg-container` 已验证目录、多块/固实索引、分卷链接及跨卷边界等 370 项检查，匹配 24 份参考元数据（两个短 LEA 仅验证元数据）。内容解码、逐块 CRC、加密及产品入口仍在实现。参考程序现独立检查 CRC，已将两个短 LEA 文件返回全零的结果更正为已知解码缺陷；另保留属性解析异常和高压缩比输出上限，详见 `tests/fixtures/archives/egg/README.txt`。

`test:archive-authentication` 覆盖 ZIP 的 AES AE-1/AE-2 认证码、AE-1/ZipCrypto CRC、存储/Deflate/XZ、空文件以及解压/拖出/修改前验证。底层关闭 API 同时携带数据描述符输出参数，确保读取描述符不会覆盖认证失败。生成归档由独立 7-Zip ZIPX 处理器校验；空文件 XZ 兼容修复另经外部 7-Zip 25.01 验证。七份固定外部样本覆盖无描述符 WinZip AES128/256 及 AES256 BZIP2/LZMA/PPMd8/XZ，来源、哈希及许可位于 `tests/fixtures/archives/encrypted-zip/`。minizip 修改与许可说明见 `vendor/archive/minizip-ng/ONE-PATCHES.txt`，精选证据见 `verification/archive-authentication/latest.json`。

基础检查使用 `npm run typecheck`、`npm run check:docs`；归档服务、格式、修改、恢复、外部编辑及系统入口使用 `package.json` 中对应的 `test:archive-*` 和相关验证脚本。新增格式使用 `test:archive-formats` 与 `test:archive-formats-ui`，固定样本、哈希与许可位于 `tests/fixtures/archives/`；未知大小的磁盘/字节/时间边界由 `tests/archive-space.cpp` 验证。必要时通过 `npm run verify -- <用例>` 留存有界结果。结束后回收 profile 和过程数据，保留精选证据及方法。
