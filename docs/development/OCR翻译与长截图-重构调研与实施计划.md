# OCR、翻译、公式识别与截图采集重构

调研日期：2026-10-13。源码基线：`caa91ba`（0.16.24）。本轮仅完成源码核对、公开方案调研和实施设计，未更改功能、下载模型或调用付费服务。下文效果与性能均未在 One 中实测；上游指标不等于本机结果。当前任务状态统一见 [TODO](TODO.md)，原 Frame 迁移验收仍暂停。

## 1. 建议结论

| 范围 | 建议 |
| --- | --- |
| 普通 OCR | 本地优先，以 PP-OCRv6 small/medium 的官方 ONNX 模型为首选候选，与 v5 和当前 Tesseract 同样本比较后定默认档。复用已有 ONNX Runtime；不要求用户安装 Python。 |
| 图上选字 | 建立统一的图片文字几何数据和选择层，支持拖选、跨行、复制及局部翻译。不是给原图加一个全图文本框。 |
| 翻译 | 专用翻译服务适配器 + 现有 AI 服务；AI 仅选择已有服务/模型，不再填写另一套 AI 地址和密钥。 |
| 原图翻译 | OCR 分段 → 翻译 → 原文字区域处理 → 译文排版；优先保证文字和位置正确，再处理复杂背景。保留可编辑文字层和原图。 |
| 长截图 | 普通截图选区工具栏增加“长截图”，默认手动滚动自动采集，也支持自动滚动；两种模式共用采集、稳定检测和拼接引擎。 |
| 多窗口 | 优先重构为不可变快照：保存/编辑已经取得的像素不依赖源窗口继续存在；重新采集才检查实时窗口。 |
| 表格识别 | 删除专属入口、桥接和实现；保留普通 OCR 识别表格中的文字，不影响文件预览及已有表格工具。 |
| 公式识别 | 本地专用模型、SimpleTex 专用接口、现有 AI 视觉模型三种来源；共用结果编辑和公式预览。 |

## 3. OCR 选型与图上选字

### 3.1 方案比较

| 方案 | 适用性 | 建议位置 |
| --- | --- | --- |
| Tesseract.js | 已集成、可离线、迁移风险小；当前使用的语言/版面配置有限。 | 保留作基准及兼容回退，是否长期保留由实测决定。 |
| PaddleOCR PP-OCRv6 | 官方已发布 tiny/small/medium；small/medium 覆盖 50 种语言，tiny 为 49 种且不含日文。官方提供 ONNX 模型。 | 优先评估 small 为默认、medium 为高精度；不能仅因 tiny 小就选为唯一引擎。[算法说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.en.md)、[官方 ONNX 模型](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_rec_onnx) |
| PP-OCRv5 / RapidOCR | 部署资料及 ONNX 推理路径成熟；RapidOCR 提供词级框输出，可参考前后处理和坐标还原。 | 与 v6 同测；RapidOCR 是部署工具，不是另一种独立识别模型。不直接假设其当前发布版完整支持 v6。[模型列表](https://rapidai.github.io/RapidOCRDocs/main/en/model_list/)、[词框输出](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/usage/) |
| PaddleOCR.js | 官方提供浏览器 SDK 和 Worker 用法，当前示例以 PP-OCRv5 为主。 | 原型比较其前后处理复用价值；不默认在主窗口线程推理，也不假设 SDK 与所有 v6 模型直接兼容。[官方部署文档](https://www.paddleocr.ai/latest/version3.x/inference_deployment/cross_platform/browser.html) |
| Windows AI Text Recognition | 系统能力有硬件/运行环境条件，当前官方支持表中该 OCR API 需要 Copilot+ NPU。 | 可作为未来增强，不能作为全用户默认依赖；不要与旧 `Windows.Media.Ocr` 混为一谈。[官方支持表](https://learn.microsoft.com/en-us/windows/ai/apis/) |
| 视觉大模型/云 OCR | 可补充困难图片与复杂版面，但有延迟、费用、上传和文字幻觉问题，坐标稳定性也需验证。 | 用户选择的增强来源；不静默上传，也不让模型猜出的文字冒充原图精准位置。 |

One 已有 `onnxruntime-node`、Sharp 和模型下载/校验能力。优先在独立推理 Worker 中运行检测、方向处理、识别和后处理，复用模型缓存；模型首次使用按需下载，记录版本、字典、前后处理配置、大小、哈希和许可，原子完成安装。代码许可和具体权重许可分别核对，不只看仓库首页。

### 3.2 图片文字数据与选择交互

统一输出 `document → blocks → lines → tokens`，每个节点有稳定 ID、阅读顺序、原图像素坐标、四边形、文字与可选置信度；同时记录引擎/模型版本、图片哈希、预处理到原图的变换。中文尽量支持字级、英文支持词内选择；优先采用引擎词框与识别对齐信息，不能把整行平均分宽后宣称精确字框。近似位置单独标记并实测。

交互设计：

- 原图是主工作区，图上直接拖选；双击词/短语、三击行、跨行拖选，选区遵循阅读顺序而非单纯矩形相交。
- 选择层使用几何高亮和透明可访问文本层；提供 Ctrl+C、Ctrl+A、Shift 扩选与键盘操作。区分选字、框选局部识别、拖动画布，按住空格平移。
- 缩放、平移、旋转、适应窗口、不同 DPI 都使用同一坐标变换；视觉高亮和实际复制范围保持一致。
- 选中后浮出紧凑操作条：复制、翻译、重新识别。右侧可展开结果/校正面板，选择与文字列表联动；修改文字不擅自移动原图坐标。
- 长图片采用分块识别和可视区渲染，块边重叠去重、保留全图坐标，解决现有最长边 8192/1200 万像素对长图的限制；大图不一次解码和推理全部内容。
- 选择层作为共享组件接入独立 OCR 窗口、图片预览和截图编辑器；用户在图片上点击“识别文字”即可进入选字模式，沿用当前图片、缩放和位置，不强制跳到另一个纯文本窗口。识别按需运行，网络增强由用户选择。

验收同时看识别字符错误率、选字位置、阅读顺序、冷/热耗时、峰值内存和取消响应。现有 `confidence` 不能直接与其他引擎数值比较。

默认引擎必须在中英屏幕截图主样本上优于当前 Tesseract，并检查每类样本是否出现明显退化；具体阈值在 A 阶段测量后冻结。v6 未通过时选择更合适的 v5 配置或继续优化，不为追新直接替换。

## 4. 翻译与现有 AI 服务统一

### 4.1 服务接入

提供统一 `TranslationProvider`：输入为带 ID 的段落、源语言/自动检测、目标语言、可选术语；输出逐段译文、实际服务/模型、状态。每个服务声明批量、语言检测、术语、图片翻译及额度限制，超长文本按服务规则切分。

| 来源 | 计划 |
| --- | --- |
| 现有 AI 服务 | 直接选已配置的 Profile/模型；文本模型可翻译 OCR 文字，公式识别必须选择经确认可收图的模型。OpenAI 兼容接口、Ollama、LM Studio、Codex 均走当前适配层；每个服务能否收图分别验证。 |
| Azure / DeepL / Google Cloud | 首批专用文本翻译适配器。协议和认证不同，不能把所有接口伪装成 Chat Completions。[Azure](https://learn.microsoft.com/en-us/rest/api/translator/translator/translate?view=rest-translator-v3.0)、[DeepL 官方 API](https://github.com/DeepL/openapi)、[Google Cloud](https://docs.cloud.google.com/translate/docs/basic/translating-text) |
| 腾讯 / 百度 / 有道 | 同一套适配器接口下的后续接入，按可用账号逐项验证；不使用网页抓取或不稳定的免密接口。[腾讯图片翻译](https://cloud.tencent.com/document/product/551/118482)、[百度文本翻译](https://fanyi-api.baidu.com/doc_bd/21)、[有道批量文本翻译](https://ai.youdao.com/DOCSIRMA/html/trans/api/plwbfy/index.html) |

专用服务的认证保存在同一设置体系的服务连接中；它们不是另一套 AI 聊天服务。识别窗口只展示服务选择和“管理服务”入口。禁止在 renderer 读取明文密钥。AI 任务不写入普通聊天历史，沿用当前并发上限和取消/超时机制；配置修改不能让旧任务结果覆盖新选项。

增加内部 `AIService.runTask`，支持任务用途、服务/模型引用、文字/图片、可选结构化输出和所属窗口；不开放任意提示词执行入口给其他不相关窗口。AI 多段翻译通过段落 ID 校验缺失、重复和乱序，失败时显示具体段落并允许重试；正常译文保留。纯文本翻译默认只发送文字，公式/视觉翻译明确发送图片。

### 4.2 原图翻译

默认管线：冻结原图 → OCR/段落归并 → 分段翻译 → 生成文字掩膜 → 背景处理 → 按原区域排译文 → 可编辑结果。

- 先覆盖文档、聊天截图和网页的水平文字：同色/简单渐变背景按区域估计颜色处理，保留图片和装饰。
- 复杂背景评估项目现有 MI-GAN 修复能力是否适合小字掩膜，不直接承诺无痕；掩膜只覆盖文字笔画，避免抹掉图表/线条。不合适时明确使用可读底板，并允许切回原图。
- 按块拟合字号、行距、换行和对齐；译文变长时给出溢出提示/展开区域，不能无下限缩小字体或遮盖相邻块。竖排、旋转、混合方向列入专项验收。
- 工具条：原文/译文切换、目标语言、服务、重新翻译、复制/保存；支持按住查看原图，点击译文块修正。编辑器保留原图、文字层和翻译版本，导出时再合成。
- 腾讯已有返回翻译图片的专用接口，可作为可选快速来源，但其输出为 JPG；是否同时保留可编辑分段信息另行核对，不能默认与本地可编辑翻译层等价。[官方说明](https://cloud.tencent.com/document/product/551/118482)

旧配置迁移：已有 chat 连接转成 AI Profile 引用，Azure 转成专用翻译连接；按协议/地址/模型及主进程中的凭据匹配去重，不能只按名字合并。旧完整 endpoint 与 AI baseUrl 语义不同，需验证转换。成功保存、回读和备份兼容验证后才清理旧记录；解密失败保留原记录并提示重新配置。

## 5. 长截图：手动与自动共用一条采集管线

### 5.1 调研判断

长截图没有通吃全部应用的滚动接口。ShareX 的公开方案是选窗口/区域、滚动、采帧和图像匹配；其官方文档明确指出固定侧栏、页头页脚、动画和 hover 效果会干扰拼接。[ShareX 长截图](https://getsharex.com/docs/scrolling-screenshot)

微信/QQ 的内部算法没有在本轮找到可核实的官方实现资料，采用用户描述的交互作为目标，不声称复制其内部算法。浏览器整页协议只适用于有权限控制的浏览器页面，不能替代任意桌面软件选区截图。

### 5.2 使用流程与窗口布局

1. 普通区域截图完成框选后，工具栏出现“长截图”；沿用当前显示器和选区，进入时不要求再选一次。多窗口合成、自由形状等不适用来源不显示该按钮。
2. 默认“手动滚动”：用户滚鼠标、触控板或拖动滚动条，系统自动检测稳定帧并拼接；无需每滚一屏再点采集。
3. “自动滚动”：确认目标窗口和滚动点后开始；可以随时暂停、改成手动并继续已有结果。不能因为操作栏获得焦点就使自动模式无法开始。
4. 选区外侧放紧凑浮动条：模式、暂停/继续、撤销、完成、取消；一侧是可折叠的窄缩略长图，显示当前视口位置和新增区域。避免现有截图中左侧超长预览挤压内容。
5. 完成后进入统一图片编辑器；拼接纠错、裁剪、标注、复制、保存都有明确入口。高级固定栏排除/匹配参数放入设置面板，默认不要求填写像素偏移。

### 5.3 引擎重构

状态分离为“准备/手动运行/自动运行/暂停/待确认/完成”，用户模式与匹配状态分开。两种模式共用原生采集、稳定检测、变化检测、匹配、去重和增量结果。

- WGC 采集会话持续复用；评估原始像素通道，避免每帧在主进程反复 PNG 编解码。工作线程处理匹配，界面仅接收降采样预览和状态。
- 自动滚动步长根据上次实际位移调整，保留足够重叠；等待页面稳定和新增内容，而不是仅依靠当前 140ms 等待和 250ms 调度。慢加载/平滑滚动允许延迟，重复帧不是立即到底。
- 多尺度位移搜索与局部一致性验证；弱纹理、重复列表、动态广告应降低匹配置信度。只做必要平移，不能用透视拉伸“拼上”文字。
- 固定页头页尾保留一次，匹配时排除固定区域/侧栏/滚动条；自动检测提供可视化修正。只有局部动画时屏蔽该区域，不能全图一直等待。
- 手动快速滚动导致无重叠时暂停追加，保留已拼结果，提示滚回一段找回衔接；反向滚动用于定位恢复，不重复追加。低置信度帧不自动硬拼。
- 自动输入只作用于已确认目标；目标关闭、遮挡或失去可用滚动条件时暂停，不把滚轮发送给其他程序。触控板、拖动滚动条也能通过图像变化采集。
- 平铺条带/磁盘暂存处理长图，遵守内存、磁盘和最大输出限制；达到上限时允许保存已有内容。取消/失败仅回收本会话自有缓存。
- 窗口边框、浮动条、预览自身排除采集，无法排除时隐藏采样；不假设所有远程桌面都支持捕获排除。不同 DPI、负坐标和显示器变化单独处理。

## 6. 多窗口快照与表格识别删除

多窗口先做最小复现：选择 2～4 个窗口 → 截图 → 移动/缩放/最小化/关闭源窗口 → 标注 → 保存，同时分别测试“不刷新”和“主动刷新”，记录会话 ID、版本、错误分支、HWND/PID、前后尺寸和显示器签名。不记录图片内容或密钥。

设计改为 `CaptureSnapshot` 持有冻结图层、尺寸、布局和版本；源窗口身份只用于采集/刷新。保存、复制、OCR 和编辑使用这个快照。源关闭或显示器重排不应使已取得的离线像素无法导出；贴图定位等实时操作单独降级。

首次采集仍需检查 HWND/PID 和帧有效性，防止复用错误窗口；位置变化与尺寸变化分开处理，可有限重试重新定版。刷新重新生成候选快照，成功后原子替换，失败保留旧快照。布局变大不再直接判定原快照失效；若影响已有标注，保留旧版并由用户确认重采，不能静默错位。保存对话框打开、失焦、同名窗口、混合 DPI、透明窗口都纳入回归。

删除“表格识别”涉及识别窗口页签/按钮、截图流程入口、IPC/preload/types、表格重建/校正/复制导出实现、测试和用户说明；旧配置中的动作明确提示已移除，不静默改成另一种功能。仅删除识别子系统专属代码，不删除 Excel/CSV/工作簿预览、JSON 表格展示等独立能力。

## 7. 公式识别方案

| 方案 | 调研事实与取舍 |
| --- | --- |
| SimpleTex | 提供专用公式 API，标准 `/api/latex_ocr`、轻量 `/api/latex_ocr_turbo`，返回 LaTeX 和置信度。适合作为云端专用来源。官网演示不是离线模型下载，本轮未找到官方可下载权重；文档计费/赠送说明存在不同口径，实施时以账户控制台为准，不在产品中写死免费额度。[官方 API](https://doc.simpletex.cn/zh/api/) |
| PP-FormulaNet_plus | 官方有 S/M/L。文档中 S 权重约 248 MB，M 约 592 MB；S 偏英文公式，M/L 增强中文公式。适合优先做本地候选。CPU、Windows 推理与转换路径必须原型验证，不能把 Paddle 推理模型直接当作现成 ONNX 包。[模型文档](https://www.paddleocr.ai/main/en/version3.x/module_usage/formula_recognition.html) |
| UniMERNet | 专门图像到 LaTeX，仓库提供 tiny/small/base，下载说明约 441 MB/773 MB/1.3 GB；官方采用 Python/PyTorch 环境。作为复杂、截图和手写公式的比较候选，默认安装器不捆绑整套运行环境。[官方仓库](https://github.com/opendatalab/UniMERNet) |
| pix2tex / LaTeX-OCR | 专门方程图片转 LaTeX，MIT 仓库，作为轻量方案与识别质量基准；不能推断其覆盖全部中文、手写和复杂多行公式。[官方仓库](https://github.com/lukas-blecher/LaTeX-OCR) |
| 现有 AI 视觉服务 | 复用已有 Profile/模型、图片传输、密钥和取消；提示模型只转写不求解。提供图片裁剪和结果核对，不能伪造模型置信度。 |

建议先打通现有 AI 视觉任务 + SimpleTex 专用适配器，同时完成本地 S/M 候选的实测；本地模型通过体积、许可证、CPU 性能和准确率门槛后接入模型管理。若 ONNX 转换不可靠，先提供用户已有的本机服务端连接，不为了“离线”给所有用户增加大型 Python 包；完整内置本地能力仍作为后续明确交付项，不能用云端替代后宣布完成。

结果界面统一为裁剪原图 + 可编辑 LaTeX + KaTeX 预览；支持复制 LaTeX、复制公式图片、导出 SVG/PNG。矩阵、分段、上下标、多行和手写样本分别验收。KaTeX 不支持的合法语法保留原文并提示，不能丢弃或执行任意 TeX/外部命令。

## 8. 实施阶段与交付门槛

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：稳定性与选型原型 | 复现多窗口问题；建立冻结快照；梳理表格删除影响；OCR v6/v5/Tesseract 及公式候选小样本比较。 | 快照保存不依赖源窗口；基准有可重复结果；模型/运行时/许可清单明确。 |
| B：OCR 与图上选字 | 统一文字文档、模型安装、图上拖选、阅读顺序、文字校正与长图分块。 | 全图/局部/跨行复制正确；缩放/DPI/旋转不漂移；性能与内存通过预先定义的样本门槛。 |
| C：统一服务与公式 | AI 任务 API、旧连接迁移、首批翻译适配器、AI/SimpleTex 公式入口；接入已通过原型的本地公式模型。 | 不新增第二套 AI 配置；删除/换模型/取消/迁移可恢复；公式输出可编辑可预览。 |
| D：原图翻译 | 分段译文、掩膜、背景处理、排版、编辑、原图对照与导出；再补国内专用翻译服务。 | 无漏段/乱序；不破坏非文字区域；复杂背景和文字溢出有可用退路。 |
| E：长截图重构 | 截图工具栏入口、手动自动采集、自动滚动、共享匹配、紧凑 UI、撤销/恢复/编辑。 | 标准样本不重复不缺行；低置信度不硬拼；可切模式、保存已有结果和取消。 |
| F：收口交付 | 表格识别彻底移除、旧配置处理、文档/快捷入口、目录包/安装器回归。 | 源码/开发版/安装版一致；运行数据不串版本；用户实际场景验收独立记录。 |

阶段 A 完成后冻结候选版本和默认档；B 与 C 共用任务和数据协议，D 依赖 B/C；E 在快照/采集边界稳定后推进。全程复用 One 公共按钮、弹窗、SegmentTab、主题和动画规范，不把来源应用整套样式再次复制进来。

### 验收样本与指标

- OCR：至少 60 张分层样本，覆盖中英混排、小字、深色、低对比、旋转、双栏、聊天、代码、日文和超长图；人工标注文字及关键几何区域。记录字符错误率、漏检/错检和选择定位误差。
- 公式：至少 40 张，含打印、截图、手写、分式、矩阵、分段、多行与中文夹杂；检查符号和结构正确性，不以 LaTeX 字符串逐字相同作为唯一标准。上游 CDM 可作参考。
- 翻译：至少 30 张文档/聊天/网页/复杂背景样本；分段一致性、可读性、溢出、非文字区域保留和原图切换人工验收。无账号的服务只做协议桩测试，不能标为真实服务验证通过。
- 长截图：浏览器、资源管理器、聊天、PDF、不同 UI 框架，含懒加载、固定栏、动画、重复行、反向/快速滚动、拖动滚动条、触控板、多屏缩放；至少 20 个脚本/人工场景，核对缺行、重复和可恢复性。
- 多窗口：至少 15 个状态场景，覆盖源窗口移动/关闭/缩放、同名 HWND/PID 身份、保存对话框失焦、主动刷新失败、显示器变化与混合 DPI。
- 冷启动、热运行、峰值内存、模型下载/取消、请求超时、窗口关闭和版本升级均记录；具体耗时门槛由 A 阶段实测冻结，不先承诺未经验证的毫秒数或准确率。

## 9. 尚未验证的关键事项

PP-OCRv6 在目标 Windows CPU 和已有 ONNX Runtime 下的实际耗时及前后处理兼容；中文细粒度选择定位；本地公式的自回归解码/转换与权重许可；现有 Codex 和各服务实际视觉模型能力；复杂背景擦字质量；真实长截图目标的滚动注入和遮挡行为；多窗口报错的实际发生路径。以上是实施前的验证门槛，不是已经解决的结论。
