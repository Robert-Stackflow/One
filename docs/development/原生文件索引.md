# 原生文件索引

运行版与磁盘原型共用匹配规则、目录优先级和记录恢复逻辑。默认启动仍进入可修改索引服务；只有显式传入 `mapped-*` 命令才运行诊断原型，不自动迁移用户缓存。

## 模块

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 服务启动、请求调度、查询与扫描协调 |
| `rows.rs`、`path_key.rs`、`stored_path.rs` | 可修改记录、共享目录前缀与路径拼写 |
| `search_access.rs`、`priority.rs` | 两种索引共用的匹配接口、父目录复用与目录优先级 |
| `catalog.rs` | 共用的路径元数据、目录范围与分批子项读取接口 |
| `enumeration.rs` | 分批文件扫描与可取消的接收方接口 |
| `filesystem.rs` | 后端无关的文件变化处理、目录拼写与类型规则 |
| `incremental.rs`、`maintenance.rs` | 运行版修改适配、启动验证及定期验证 |
| `cache.rs` | 运行版快照、完整事务增量、持久化与锁 |
| `cache/stream.rs` | 只读迁移解析，复用缓存格式，不恢复完整索引 |

| `mapped_probe/import.rs` | 已有缓存的流式转换，乱序输入使用有界外部排序 |
| `mapped_probe/scan.rs` | 无缓存首次构建，复用目录扫描、外部排序和镜像写入，处理取消及中断暂存 |

| `mapped_probe/store.rs` | 版本发布、读写调度、共享读取视图、后台合并、重放与中断恢复 |

## 精确匹配的父目录复用

全部搜索词带引号且不含路径分隔符时，共用匹配器先用名称与父路径的字符掩码排除不可能匹配的记录。随后先匹配文件名，仅在名称未匹配时为当前父目录记录各词是否出现；同一父目录的后续记录直接复用判断。文件名字符掩码缺失时跳过名称读取，保留完整名称／前缀／子串／父目录的原评分及目录加分。普通模糊、拼音、含路径的混合条件和具有独立展示名称的程序结果继续使用原匹配规则。

暂存仅随本次查询词数增加，父目录改变时覆盖，不增加每文件缓存或常驻索引字段。查询保留索引读锁或映射所有者，父目录文字引用在整个匹配期间有效；以其地址和长度识别共享前缀。模型对照覆盖父目录命中、多个词、大小写、Unicode、UNC、根目录和特殊路径拼写，磁盘行与普通行共用同一匹配器。此处代码改进的实际部署及性能结论以[优化进度](优化进度.md)中的验证记录为准。

## 诊断入口

- `mapped-build CACHE OUTPUT CONFIG_JSON`：完整恢复后构建镜像，保留为对照基线。
- `mapped-import CACHE OUTPUT CONFIG_JSON`：流式转换已有快照及完整增量事务，原文件不变。
- `mapped-scan OUTPUT CONFIG_JSON`：无缓存首次扫描，以分批磁盘排序生成镜像，不恢复或构造完整内存索引。
- `mapped-query IMAGE`：只读查询已生成镜像。
- `mapped-store SEED STORE_DIR`：版本存储与后台合并；重启可使用已持久化版本。

流式转换与后台合并使用同一个镜像写入器。输出完整保存后才发布；取消或错误保留此前输出。变更层有数量和文件大小限制，父目录复用表有数量与文字预算，但这些不是任意输入下的严格堆内存字节保证。记录表按 64 字节对齐，必要时追加一个未引用的父目录记录。

首次构建使用现有的优先级扫描计划，重叠根目录与优先级子区域互相排除。暂存批次最多 8,192 项或约 4 MiB 路径文字，使用共用 16 路分层外部排序；不可修改镜像逐包生成。路径冲突保留最后枚举的记录，序号贯穿多层合并；旧缓存转换仍严格拒绝重复键。达到条目上限时先在磁盘上合并、核对唯一数量，重复项没有用完预算则继续当前扫描，不以全量内存集合计数。

构建暂存目录有独占锁及所有权标记，自动排除于扫描。完整镜像在暂存目录写完、同步后才替换目标；取消、保存或替换失败保留旧目标。新进程可清理已确认属于该构建器的中断文件，未知内容或嵌套目录使其拒绝复用，不递归删除。诊断命令为一次性构建，调用方可通过进程退出取得完成结果；实际服务仍需将可取消构建、读取、监听和首次可查询状态衔接起来。

## 文件系统扫描调度

共用扫描器保留四个工作线程，最多安排 64 个正在执行或等待的子目录任务。父目录记录在子任务启动前送出，直接文件以最多 1,024 条记录分包，不再先收集整个目录的全部子目录。任务满时使用显式深度优先栈继续扫描，暂停的父目录仅保留枚举器与空包，不继续生成待执行闭包，也不递归调用扫描函数。16 包接收通道提供背压；接收方拒绝、取消或报错时关闭通道并等待工作线程结束。

这些限制控制目录宽度造成的暂存，不能视为整个扫描流程的严格字节上限：深层目录仍需保存枚举器，路径长度、索引本身、持久化和目录校验的已见集合仍影响内存。正常后端和磁盘诊断后端共用此扫描器，文件系统更新的完整主体折叠仍有额外磁盘开销。

2026-10-04 已载入实际 dev 的默认可修改索引入口；仅部署扫描调度优化，没有切换为磁盘诊断后端，也未包含尚未完成验证的查询实验。部署后真实搜索、目录监听及缓存加载正常，常驻索引私有提交仍约 1 GiB。部署与性能验证记录见[优化进度](优化进度.md)。

## 目录验证与变更

运行版的启动验证和目录变更读取使用 `FileCatalog`，与磁盘诊断后端共用目录范围、路径拼写和游标语义。目录验证每批最多检查 8,192 条记录，选中目录的路径文字预算为 4 MiB；直接子项每批最多返回 512 项，跳过嵌套子树。按路径继续的游标不依赖行号，上一批末项被删除后仍可继续。

离线验证在每批检查后立即处理变化，不再保留整份索引的全部变化目录；旧子项也分批读取、释放读锁后再处理文件系统与删除。数量和文字预算限制这些暂存，并不是整个监听流程的堆内存上限：单目录枚举中的新增列表和已见路径集合仍需后续优化。

两种服务支持 `metadata`、`directories`、`children` 请求，用于对照和后续接入，不改变搜索取消范围。运行版的修改、首次扫描和缓存持久化仍使用可修改索引；共用目录接口不代表磁盘版本存储已经成为默认后端。

文件变化处理使用可报错的 `FilesystemIndex` 修改接口；扫描器把记录批次交给接收方，接收方拒绝、出错或取消时先停止生产线程并关闭接收通道，再等待线程退出。运行版适配器保留代号检查和现有缓存写入；内存与磁盘增量统一使用 `cache::Change`，旧缓存编码与修改顺序不变。启动校验的并行时间戳检查、分批目录读取及缺失根目录恢复共用 `filesystem::verify`。

磁盘版本存储的诊断 `refresh` 请求接收 `config`、`paths` 与 `offline`，在独立增量副本上执行文件变化事务。先保存完整增量，再替换可查询状态；没有变化时不重写。目录改名、删除、大小写与文件／目录类型变化沿用运行版规则，内容写入不更新名称索引；存储目录自动排除。后台合并期间保存后的小型修改按最多 1,024 项分包进入重放历史。`cancel-refresh` 或较新的 `refresh` 使旧事务取消；取消及保存失败保留此前确认状态，已经完成持久化提交的小型事务则继续确认成功。

诊断存储的修改与读取分别调度。读取使用最后确认的主体与不可修改增量，一个查询始终读取同一版本；保存成功后发布新快照再回复修改请求。版本切换前准备好文件读取句柄，旧主体在最后一个读者结束后回收。并发查询、目录校验及后台合并共用同一只读映射，增量通过共享引用使用；快照只保留映射的弱引用，空闲后解除大视图，仅保留文件句柄。映射始终禁止写入、删除，所有借用依赖其所有者，跨线程的只读映射约束记录在实现中。已有缓存与文件映射数据不会变成全量堆记录。

文件系统事务按最多 18,000 项修改或 4 MiB 重放文字分段，接近增量容量时也提前折叠。每段通过共用写入器流式生成尚未发布的主体，释放上一段后继续；增量自身仍有 20,000 行／删除区间和 8 MiB 编码限制，编码超限也折叠后继续。所有段成功后才切换版本，中间查询始终看到此前确认的版本。失败或取消回收私有输出，完整发布后取消旧后台合并，避免其覆盖新版本。这是文件系统更新入口的继续机制，诊断 `apply` 入口仍保留原有容量拒绝。

当前每次折叠会重新流式写入完整主体，大批修改仍有明显磁盘开销。首次构建现使用独立的分批排序入口，但应用服务及真正监听接入仍待完成，不会在此阶段切换实际 dev 的默认索引。诊断磁盘后端尚未提供程序／设置结果，它们不读取文件记录，因此仅检查主体头部与版本，不再遍历全部文本；实际程序／设置混排仍须接入。

可修改索引删除子树每批最多暂存 1,024 个共享路径键，释放这一批后继续，不再收集全部后代；同前缀的相邻目录不会被删除。目录枚举出错时保留未确认的旧子项，目录签名置零，供下次校验重试。此处只限制删除的路径暂存，槽位空闲列表、路径池和扫描器的待处理目录仍可能占内存。

扫描结束先安排最终缓存保存，再清除工作标记并发出完成通知；目录验证结束也在发出通知前清除标记。立即退出仍会等待已安排的保存，只有确实中断的扫描才使目录签名失效，避免完成通知与退出之间的竞争导致下次重复校验。

## 验证与边界

Rust 测试覆盖路径、拼音、类型、优先级、缓存格式、乱序与重复输入、变更和发布失败。仓库根目录的隔离验证使用真实缓存副本，检查完整前百项、总数、当前目录首批、取消、内存、后台更新及进程中断恢复：

```text
node scripts/verify.mjs mapped-import-performance
node scripts/verify.mjs mapped-first-build-native
node scripts/verify.mjs mapped-compaction-performance
node scripts/verify.mjs search-priority-native search-local-native
node scripts/verify.mjs index-catalog-native index-reconcile-native
node scripts/verify.mjs index-watch-native
node scripts/verify.mjs index-directory-scan-performance
node scripts/verify.mjs mapped-filesystem-native
node scripts/verify.mjs index-incremental-09 index-core-performance
node scripts/verify.mjs index-literal-performance
```

目录接口对照覆盖约 459 万条真实缓存记录；运行版重新校验使用自有文件验证离线变化、取消恢复和持久化重启，`index-watch-native` 单独验证真实递归 Windows 通知经当前 `SearchService` 到候选原生程序的交付。`mapped-filesystem-native` 在真实冻结索引旁新增自有目录，验证磁盘事务、校验期间并发搜索及版本一致性、后台重放、21,000 项自动分段发布、第二次折叠时取消、发布失败重试和重启，但不是实际应用的监听接入；可用 `ONE_MAPPED_REFERENCE` 指定保留的不同候选，在同一冻结主体及文件变化上比较并发工作集。应用服务接入、高效无缓存首次扫描、程序和设置混排、主体损坏恢复、冷存储响应仍需完成。详细测量见[文件索引内存与驻留](../research/文件索引内存调研.md)。
