# One 技术栈与代码结构

适用于当前 Windows 桌面应用。依赖与版本以 [package.json](../../package.json)、锁文件和 vendor 来源记录为准；当前功能与任务见[TODO](TODO.md)，早期选型及逐版本实现见[历史说明](../history/projects/早期技术栈与实现说明.md)。

## 技术栈

Electron + TypeScript 分离主进程、预加载和界面；esbuild 打包主进程/预加载，Vite 构建界面。界面使用现有 TypeScript 模块与共享组件。Windows 集成及归档引擎使用 C++，文件索引辅助程序位于 Rust 模块；原生实现按现有构建脚本编译和复制到运行目录。

## 源码目录

| 目录 | 职责 |
| --- | --- |
| [src/main](../../src/main) | 窗口与应用生命周期、服务、任务、文件访问、系统集成和私有 IPC |
| [src/preload](../../src/preload) | 固定页面 API 与事件，不暴露完整 Node 或 IPC |
| [src/renderer](../../src/renderer) | 页面、独立窗口、共享交互组件、样式与渲染 |
| [src/shared](../../src/shared) | 跨进程类型、协议、纯逻辑与校验；保持无页面/主进程副作用 |
| [native](../../native) | Windows C++ 辅助程序；归档在 archive，Rust 索引在 search-engine |
| [assets](../../assets)、[vendor](../../vendor) | 产品资源、固定第三方源码/二进制及对应来源和许可 |
| [scripts](../../scripts) | 开发启动、构建、打包、文档检查与验证工作区管理 |
| [tests](../../tests) | 自动检查、受控夹具、真实原生与 Electron 操作测试；运行数据输出到 work |
| [installer](../../installer)、[build](../../build) | 安装器源码及构建资源；不作为生成缓存删除 |

不按文件大小机械拆分模块。新增逻辑归入已有职责层，变更入口时同步协议、调用方与相关检查；源码目录中不存运行 profile、构建中间文件或截图。输出分类与保留规则见[开发与缓存](开发与缓存.md)。

## 调用与安全边界

查找实现优先沿功能入口及相同前缀定位，不为目录统一移动现有模块：

| 事项 | 入口与配套模块 |
| --- | --- |
| 应用启动与窗口 | [main/index.ts](../../src/main/index.ts) 注册生命周期和服务；[renderer/app.ts](../../src/renderer/app.ts) 组织主界面 |
| 归档 | [archive-service.ts](../../src/main/archive-service.ts)、[archive-view.ts](../../src/renderer/archive-view.ts)；编辑会话、修改与恢复使用独立 `archive-*` 模块 |
| 搜索与索引 | [search-service.ts](../../src/main/search-service.ts) 协调搜索；[native/search-engine](../../native/search-engine) 实现原生索引 |
| 预览 | [preview-service.ts](../../src/main/preview-service.ts) 与各 `preview-*` 解析/页面模块 |
| 文件工具 | [file-tools-service.ts](../../src/main/file-tools-service.ts)、worker 与 engine；[共享协议](../../src/shared/file-tools.ts) 和[页面](../../src/renderer/file-tools-view.ts)配套 |
| 开发及验证 | [dev.mjs](../../scripts/dev.mjs) 启动；[test.mjs](../../scripts/test.mjs) 组织检查；[workspace.mjs](../../scripts/workspace.mjs) 管理用例与样本；清理操作见[目录管理](开发与缓存.md) |

测试目录沿用按功能命名的文件：`archive-*`、`preview-*`、搜索及系统集成用例分别定位相关能力；复用现有辅助文件，不复制整套测试。C++ 探针与固定测试输入属于测试源码，运行产物写入 `work`，不能按文件名或后缀当作垃圾删除。

界面通过预加载的固定 API 请求主进程；主进程检查窗口角色、来源、参数及任务所有者，交给服务、worker 或原生辅助程序。长任务的进度、取消、预算和清理沿用各服务已有机制，不在页面线程同步执行。

窗口采用上下文隔离及有限接口。预览资源使用受限协议与令牌，HTML/Markdown 等内容遵循现有隔离和清理机制。外部应用调用按明确入口进行；脚本编辑不会通过默认关联直接执行。归档保存、恢复和文件回收都重新核对源对象及所有权。

全局入口 [src/main/index.ts](../../src/main/index.ts) 组织生命周期与服务注册；具体能力保持独立模块。归档、索引、预览与系统集成的详细实现分别见[归档设计](压缩与解压实现计划.md)、[原生文件索引](原生文件索引.md)、[用户指南](../README.md)。
