# 开发、构建与目录管理

日常使用独立 Dev 与当前构建验证。启动方式见[项目入口](../../README.md)，实现职责见[代码结构](技术栈.md)，当前工作见[TODO](TODO.md)。当时的环境迁移、测试数及系统入口记录见[历史验证](../history/projects/开发环境与系统入口验证.md)。

## 目录与保留规则

| 位置 | 用途与保留规则 |
| --- | --- |
| src、native、assets、vendor、scripts、tests | 源码、资源、固定依赖、许可和验证代码；纳入 Git |
| build、installer | 构建资源及安装器源码，不能按目录名当缓存清理 |
| docs | 使用说明、当前开发设计、调研和历史；[TODO](TODO.md) 是当前状态入口 |
| dist | 当前构建，可能正由 Dev 加载；不入 Git，先核对占用再清理 |
| work/dev-profile | 独立开发配置、日志与索引；保留用户开发设置 |
| work/temp、work/current | 生成样本和短期验证数据；已登记记录由 workspace 按 20 组、128 MiB 管理，活动与未登记资料须单独核实 |
| work/current/fixtures | 受控可重建样本，192 MiB 预算；测试运行时保留 |
| work/rust-search、archive-source、archive-build、cache | 现有编译与工具缓存；按脚本实际路径复用，避免重复下载或每次全量构建 |
| work/installer-output/<版本> | 安装候选及打包中间产物；验收完成前保留必要产物，不凭文件存在认定交付 |
| release/<版本> | 最多两个已验证的可运行版本；新版本校验后再淘汰旧版，运行中的版本不强删 |
| artifacts | 既有安装器交付入口；待确认验收及引用后再归并，保留唯一交付物 |
| verification/<任务或版本> | 精选日志、截图、指标等证据；不保存整套 profile 或大型样本，默认不入 Git |

目录默认相对于仓库根。可控子进程的 TEMP/TMP 使用 work/temp，不修改系统全局环境；共享依赖和工具链缓存沿用原位置。生成数据与源码分开，打包只包含运行所需文件。

## 开发与验证

`npm run dev` 启动可见窗口，使用独立 profile。界面与共享源码变化后刷新；主进程/预加载变化后正常重启。已验证当前构建、只需恢复监听器时使用 `npm run dev -- --reuse-build`；原生或依赖变化后先完成相应构建。保留正在运行的 Dev，不为目录整理重置设置或强制结束进程。

`npm run typecheck` 检查源码，`npm test` 运行逻辑检查，`npm run check:docs` 检查分类、导航和仓库内链接。`npm run verify -- <用例>` 使用隔离配置并留存有界结果；结束后回收该次样本与 profile。详细性能方法见[优化与测量](优化进度.md)。

## 清理与交付

日常清理使用 [clean-generated.ps1](../../scripts/clean-generated.ps1)。不带参数只预览 `work/current` 中的用例；确认任务结束、必要证据留存且无需复现后，显式指定用例再执行：

```powershell
./scripts/clean-generated.ps1 -CaseName 'completed-case'
./scripts/clean-generated.ps1 -CaseName 'completed-case' -Apply
```

将示例中的 `completed-case` 换成实际已完成的用例名。脚本只接受带 `.one-generated-case` 标记的独立用例，跳过或拒绝活动进程、异常活动记录、链接及未知目录；`fixtures`、Dev、共享缓存、安装候选、发布包与历史证据不在此入口的删除范围。旧 `-AllWork` 和 `-VerificationCaches` 批量选项已停用，避免沿用旧机器路径或按名称推断可删数据。兼容参数 `-WorkOnly` 仍可传入，当前入口始终只处理本仓库的用例。边界验证运行 `node tests/clean-generated.cjs`，也可由现有验证入口 `node scripts/verify.mjs clean-generated` 运行。

清理前核实生成来源、所有者标记、路径、链接、证据和活动进程。递归操作限制在已确认的生成目录，遇到未知文件或链接时保守保留；不以被忽略或目录名称作为删除权限。已结束过程数据及时回收，保留必要缓存、当前构建、开发配置、待验收安装候选和唯一证据。

需要交付时沿用 package 与安装器脚本：目录包进入 release 的对应版本，安装候选进入 work/installer-output。源码、Dev、打包、安装和发布分别核验；更新时检查占用与完整运行资源。具体安装流程见[安装器](安装器.md)。
