# 开发、发布与缓存

私有源码仓库：[Robert-Stackflow/One](https://github.com/Robert-Stackflow/One)。日常修改通过 Git 提交，使用 Electron 开发模式验证，不生成小版本构建副本。

| 目录 | 用途与保留规则 |
| --- | --- |
| `src` / `native` / `assets` / `scripts` / `tests` | 受 Git 管理的源文件 |
| `docs` | 使用说明、开发资料、调研和历史文字记录 |
| `dist` | 当前构建，覆盖复用；开发时删除过期界面资源 |
| `work/dev-profile` | 独立开发配置，保留开发设置；浏览器磁盘缓存设置为 64 MiB |
| `work/current` | 固定验证目录；最多 20 组、128 MiB 记录与截图 |
| `work/current/fixtures` | 共用可重建样本，最多 192 MiB；测试运行期间不清理 |
| `work/unit` | 单元测试编译与样本，结束后删除 |
| `work/rust-search` | 唯一一份 Rust 编译缓存，不按小版本复制 |
| `release` | 最新两个可运行版本，生成新包并校验后自动清理旧包 |
| `verification` | 已迁移的历史日志和截图；不再新建按版本复制的工作目录 |

上面的路径都在 `D:\Repositories\One` 内。已将 E 盘的三个 One 目录迁移过来，核对全部文件的数量、名称和原始大小，并清理原目录。历史冗余构建与测试数据此前已删除约 29.7 GiB。

## 日常流程

`npm run dev` 启动可见开发窗口。界面和样式修改后自动刷新；主进程与预加载变更后正常退出再启动。C++/Rust 修改后重新运行开发命令。开发配置与正式版配置分开。

`npm run typecheck` 和 `npm test` 检查源码；`npm run check:docs` 检查文档分类、导航和内部链接。文档统一放在 `docs` 的四个分类内，根目录只留项目 `README.md`，修改原文件并用 Git 保留历史。

`npm run verify -- file-tools-smoke` 等验证使用隔离测试配置，结束后删除该次样本与配置，只留下有上限的结果记录。后台缓存不会为每次测试继续保留新配置副本。

需要交付时递增版本号，运行 `npm run package`。暂存目录固定为 `release/.building`，失败或结束后清理；EXE、版本和全部构建文件校验通过后移入对应版本目录，最终保留最新两版。要淘汰的旧版仍在运行时，生成前提示先退出，避免删除正在使用的程序。

## 本次验证

类型检查和 143 项自动测试通过；52 份文档的分类、导航与内部链接检查通过。

实际开发窗口已验证界面刷新和主进程正常重启。3 万项目录完整显示与定位、嵌套目录交互、结构化视图、四项文件工具与概览流程均通过。目录场景只绘制 26 个树行和 24 个侧栏行，末项定位约 55 ms；这是本机短场景数据。

空间分析列表同样改为完整连续浏览，取消最大的 500 项限制；真实 30,003 项目录只保留 18 个行节点，末项定位约 49 ms。更新保留文件位置和键盘焦点，支持 Home / End / PageUp / PageDown、预览和右键操作。结果保存在固定的 `work/current/disk-list-smoke`，配置与样本结束后清理，不生成新发布版本。

矩形图取消 2,400 块绘制上限，小块间距随面积缩小；独立高亮图层让悬停不再复制整张图。明暗主题、嵌套目录、末尾文件命中及隐藏/恢复通过实际验证。30 万项完整布局模型保留内存约减少 77%，该数据不代表整个应用下降同比。验证记录复用 `work/current/disk-map-smoke` 与 `treemap-memory-smoke`。

开发版系统维护支持分别停止各页签的扫描，保留上次完整结果、选择和展开详情；隐藏页面/窗口暂停进度绘制。每类只保留最新完整报告，重复扫描的后台候选清单不再累计六份。真实 30,003 文件连续扫描八次，后台服务保留堆增量约 52 → 17.2 MiB；此数据不代表整个软件的内存降幅。固定验证使用 `maintenance-ui-smoke`、`maintenance-cancel-native` 与 `maintenance-memory-smoke`，没有生成新发布包。

这些规则限制开发和交付产物的累积。用户主动创建的索引、备份和个人文件不属于可随意删除的测试缓存。
