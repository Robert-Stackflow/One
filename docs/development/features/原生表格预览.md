# 原生表格预览

2026-10-10 开发版。按用户要求，XLSX 不再由 One 自绘表格，改由本机注册的 Windows 预览处理器展示。数据库预览继续延期；DOCX/PPTX 的后续优化单独推进。

## 范围与行为

- 当前接入 `.xlsx`。XLSM、XLTX、ODS 仍使用已有只读网格，不把 XLSX 的接入视作全部表格格式已经验证。
- 在 One 预览窗口内承载组件，保留文件导航、详情、置顶、保持窗口和默认程序打开。组件内部的工作表切换、样式、图表及搜索能力取决于已安装处理器。
- 缺少组件或关联残留时显示明确说明，提供重试和默认打开，不回退自绘网格，不自动安装/注册/修复 Office。
- 加载失败、超时或组件退出后可以重试；切换文件、重载、渲染进程异常、关闭和退出会结束对应宿主。

## 实现

`src/main/preview-service.ts` 将 XLSX 路由为 `native-office`，跳过旧工作簿解析和大型单元格 IPC。主进程给当前文件生成独立 token；`native-preview-start/bounds/stop` 仅允许预览窗口调用，启动还校验当前文件 token，renderer 不能指定任意路径或宿主 HWND。

`src/main/native-preview.ts` 管理每窗口一个会话，依次尝试 64 位、32 位宿主。每次激活最长 12 秒；加载中取消会结束等待，正常关闭先发送卸载指令，800 毫秒后仅对仍存活的自有宿主执行终止。迟到状态、过期停止指令不影响新文件。

`native/preview-host.cpp` 从 Windows 文件关联查询预览 CLSID，核对当前位数下 COM 注册，使用 `CLSCTX_LOCAL_SERVER` 激活系统代理；不把处理器 DLL 加载进 Electron。优先 `IInitializeWithStream` 只读流，其次是处理器提供的 Item/File 初始化接口；不因支持的流接口初始化失败而盲目改用其他入口。原生宿主设置 `IPreviewHandlerFrame` 站点、父窗口和显示区域，然后调用 `DoPreview`，退出调用 `Unload` 并释放站点、流和对象。不会终止共享 prevhost 或用户 Office 进程。

`src/renderer/native-office-view.ts` 立即返回清理函数，不等 COM 加载结束。区域由 DOM 测量，经 Electron zoom 和父 HWND DPI 转为物理像素；窗口和侧栏改变时更新区域。打开方式、更多菜单或模态对话框显示时，将原生区域暂时置零，避免原生子窗口盖住 HTML 菜单。关闭菜单恢复区域。原生组件将 Esc 交给宿主时关闭预览，其他键盘行为保留给组件。

## 构建与验证

- `scripts/build-preview.mjs` 构建 `One.Preview.exe` 和 `One.Preview32.exe`，已接入完整构建、dev 产物检查和 asar 解包配置。
- `npm run test:native-preview`：构建专用测试宿主，核验只读初始化、32 位回退、区域/DPI、菜单避让、重载、超时、取消、异常退出、角色/token 校验、失败重试和关闭后文件可移动。测试组件仅通过编译宏启用，不注册 COM、不修改文件关联；测试路径覆盖也只在 `ONE_TEST_MODE=1` 启用。
- `node tests/native-preview-missing.cjs`：用于本机这种缺少可用表格组件的环境，使用正式宿主核验错误页面、重试、无自绘回退和默认打开请求。测试拦截打开请求，不启动真实 Office。
- 原有自绘网格 UI 回归改用 XLSM/ODS，XLSX 底层解析样本保留给仍复用该解析器的功能。测试前应构建当前 main/preload/renderer。

本机 WPS 关联存在，但对应 COM 类未注册。因此目前已验证宿主协议和生命周期，**尚未验证真实 Excel/WPS 的样式、合并表头、图表和工作表交互保真**。低完整性代理、跨位数组件、实际组件焦点、密码文件和多显示器 DPI 切换仍需真实环境验收；不把测试组件通过等同于 Office 验收通过。
