# 条码识别设计与验收

适用于当前源码。功能已实现，自动检查范围和实际桌面捕获边界见下文；不代表已打包、安装或发布。整体范围由[产品需求](../需求.md)和[当前待办](../TODO.md)维护，使用入口见[用户指南](../../user-guide/条码识别.md)。

## 行为与结构

提供文件、拖入、剪贴板、鼠标所在屏幕框选四种输入，以及图片快速预览更多菜单入口。顶部为输入操作，工作区分图片和结果；窄窗口上下排列。图片支持缩放、适应和清空，多码时显示选择列表，单码直接展示内容。失败或取消新任务时保留上一份结果。图片通过主进程受控读取，后台 Worker 解码，选择轮廓和列表同步；复制当前内容，只有主动操作才打开不含凭据的 HTTP/HTTPS 链接。

| 职责 | 源码 |
| --- | --- |
| 数据、资源上限、链接及裁剪校验 | [shared/barcode.ts](../../../src/shared/barcode.ts) |
| 文件、异步剪贴板、屏幕捕获与会话清理 | [main/barcode.ts](../../../src/main/barcode.ts) |
| 单工作者、终止与超时 | [barcode-reader.ts](../../../src/renderer/barcode-reader.ts) |
| 图片元数据校验、像素解码、条码识别 | [barcode-worker.ts](../../../src/renderer/barcode-worker.ts) |
| 结果展示和框选交互 | [barcode-view.ts](../../../src/renderer/barcode-view.ts)、[barcode-capture-view.ts](../../../src/renderer/barcode-capture-view.ts) |

IPC 区分主窗口、预览窗口和捕获窗口权限。捕获窗口只读当前会话图像、提交裁剪或取消；主窗口关闭、取消、超时或应用退出时释放会话和窗口。框选仅针对鼠标所在屏幕，按物理图像尺寸映射裁剪坐标；最多 16 个连接屏幕，截图总像素预算按屏幕数量分摊。

不保存图片、识别内容或历史。预览图片 URL 在替换及卸载时释放；解码 Worker 在完成、失败、取消、替换及离开页面时终止。读取最多两份文件，解码并行数为一，捕获会话为一。文件先检查 32 MiB 上限，再按初始文件长度有界读取；图片先查元数据再创建像素缓冲，限制 16,777,216 像素和单边 16,384 像素。解码 15 秒硬超时，单结果文本 1 Mi 字符，总内容 4 Mi 字符，最多展示 64 个结果。

无结果不能区分未知条码格式与不可读图像，不能伪造确定原因。图片类型不支持、无法读取、损坏、超限、校验失败与取消分别有对应提示。

## 解码器选择与许可

采用 [zxing-wasm](https://github.com/Sec-ant/zxing-wasm) 3.1.5 的 reader 构建及 [image-size](https://github.com/image-size/image-size) 2.0.4。WASM 固定使用随包本地资源，不请求 CDN。当前 reader WASM 为 966,895 字节，另有构建后的 Worker JavaScript；writer 只用于测试样本生成，不进入生产页面引用。

| 方案 | 本轮实测与取舍 |
| --- | --- |
| ZXing-C++ WASM reader | 17 份独立格式样本均解码且与预期内容一致；覆盖 Micro QR、DataBar 和中文等本轮需求；随包约 944 KiB WASM，无额外平台安装步骤 |
| @zxing/library 0.23.0 JavaScript | 同一组图片解出 9/17，逐字匹配 6/17；UPC/GS1 表示差异和 Data Matrix 中文差异保留在报告，未计作正确匹配。对共同匹配的 6 份样本中位解码时间为 17.6 ms，WASM 为 47.5 ms |
| 原生 ZXing-C++ | 未做 Windows 原生部署和速度对比。根据其需要平台编译、IPC 及分发支持，选择现有 Worker/WASM 作为当前实现；不能据此声称原生性能或部署体积更差 |

比较在同一 Chromium 图片解码路径下进行，每份样本、每种引擎新建 Worker。计时不含 Worker 脚本解析及图片读取，WASM 含冷编译和加载，JavaScript 含灰度转换、四方向及反色重试；这不是总体准确率或稳态性能基准，也不支持“WASM 更快”的结论。选择依据是本轮格式与原文覆盖、后台取消和分发便利。

包装器使用 MIT；内含 ZXing-C++ 使用 Apache-2.0，版本提交为 `2ecec3f5be0ee803f6e14a5a2c7028c0cfe525b4`。[固定许可副本](../../../assets/licenses/zxing-cpp-LICENSE.txt)与依赖许可由 [notices 脚本](../../../scripts/notices.mjs)写入随包 `THIRD_PARTY_NOTICES.txt`。独立测试图片来自 ZXing-C++ 提交 `2c3dcfeffa7878950a58c1703c86774a428b0c91`，同样为 Apache-2.0；清单固定源 URL、Git blob 和 SHA-256，图片缓存在忽略目录中。

## 验收与复现

运行 `npm run test:barcode` 完成构建、样本准备及以下检查。首次准备独立样本需连接官方源，之后校验本地缓存；应用识别本身离线。

| 检查 | 覆盖 |
| --- | --- |
| [unit](../../../tests/barcode-unit.cjs) | 链接与裁剪边界；Worker 超时、取消、替换、旧回调隔离及错误释放 |
| [matrix](../../../tests/barcode-matrix.cjs) | 用户指南列出的 17 类格式，独立样本原文比对，UPC 表示规范化按上游预期 |
| [UI](../../../tests/barcode-ui.cjs) | 真实 Electron IPC、WASM、本地资源、文件/剪贴板/拖入、多码区域选择、复制、主动链接、最小宽度、退出清理与角色隔离；选择操作使用替代截图 |
| [behavior](../../../tests/barcode-behavior.cjs) | 旋转、缩小、低对比、轻模糊、局部遮挡、中文、多码与相同内容不同区域；16 Mi 像素空图、损坏/超限、按内容识别扩展名及图片预览转入 |
| [capture](../../../tests/barcode-capture.cjs) | 真实 Windows 桌面源、当前屏幕捕获、覆盖窗口加载与取消、主窗口恢复。图像仅在内存中，不保存桌面截图 |
| [design](../../../tests/barcode-design.cjs) | 重构布局的空状态、多码与键盘选择、缩放区域对齐、失败保留、清空再识别、窄窗口布局与深浅色截图 |

独立样本清单：[barcode-samples.json](../../../tests/barcode-samples.json)；[准备脚本](../../../tests/barcode-fixtures.cjs)。比较可在 `work/current/barcode/comparison` 隔离安装 `@zxing/library@0.23.0` 后运行 [comparison](../../../tests/barcode-comparison.cjs)，不将比较库加入应用依赖。测量报告及测试配置保留在 `work/current/barcode`，精选摘要放入 `verification/barcode`；旧配置清理曾受策略拒绝，不重复绕过删除。

实际桌面捕获在 2560×1440 当前屏幕完成读取和取消验证；真实桌面内容解码未作为自动检查输入。17 份格式样本及图像扰动测试证明对应样本可用，不代表所有打印质量、摄像头或未知格式均已验收。
