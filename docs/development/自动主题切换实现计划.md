# 自动主题切换实现计划

2026-10-10。按 [TODO](TODO.md) 的 Light Switch 需求推进；本页区分已验证核心与尚未接入产品的部分，不把底层测试通过等同于功能上线。

## 行为与范围

| 项目 | 设计 |
| --- | --- |
| 自动计划 | 固定本地时间、按位置估算日出日落、跟随 Windows 夜间模式三种方式；默认关闭，不改动现有主题。 |
| 作用范围 | One 自身、Windows 支持主题的应用、Windows 系统界面分别选择；默认仅 One。Windows 设置仅在用户选择对应范围并启用或执行手动切换后改变。 |
| 手动操作 | 提供浅色、深色、切换、恢复计划及快捷键。手动覆盖持续到下一个实际计划边界；夜间模式以状态变化作为边界。关闭自动计划后仍允许明确的手动操作。 |
| 现有 One 外观 | 保留当前配色、字体、密度和正常模式。自动主题只提供运行时模式，不每次改写设置。用户通过原有模式按钮停止 One 的自动管理时，不连带停止其他已选 Windows 范围。 |
| 位置 | 首期手动经纬度，不在后台进行 IP 定位或隐式申请定位权限。分别设置日出/日落前后 180 分钟偏移；未设置位置时保持当前主题并说明原因。Windows 定位服务入口经评估后单独决定，不作为已有能力承诺。 |
| 时间与生命周期 | 按当前绝对时间重算，启动、恢复、时区或时钟变化后补同步，不要求恰好在某一分钟触发。DST 缺失时间按下一个有效本地时间，重复时间不倒退已过边界。30 秒检查加下一边界定时；自动计划关闭时没有周期计时器。 |
| 不可用与退出 | 读取夜间模式失败时保持当前主题；手动切换仍可用。停止时取消外部请求并禁止过期状态发布。Windows 应用/系统写入分别报告失败，不假装已全部成功。 |

Windows 夜间模式以当前激活状态作为输入，包含系统计划与用户手动开关；其未来计划时刻不自行猜测。PowerToys 当前实现读取 CloudStore 的二进制状态，这不是稳定公开 API；适配器必须限制读取大小、处理缺失/不支持的格式，并在不可用时明确提示。不能把任意解析失败当作夜间模式已关闭。

日出日落使用 NOAA 近似方程，显示为估算时间；天气、地形及折射可改变实际日出。极昼/极夜不虚构固定切换时刻，会寻找前后真实太阳边界；手动覆盖不能因为计算窗口滚动而提前失效。

`tests/theme-schedule.cjs` 已通过 269 项检查，含 UTC、上海、纽约、奥克兰四个时区，DST 跳时/重复时段、跨午夜、暂停后追赶、连续手动切换、过期配置和服务关闭。`tests/fixtures/theme-solar-reference.json` 的 72 组经纬度/日期由 NOAA 独立的 Julian-century 计算器生成；当前样本最大差异 4.35 分钟，不是全球所有日期的精度保证。生成方式为 `node scripts/build-theme-reference.mjs`，默认复用已下载参考，明确加 `--refresh` 才重新下载；产物记录来源和 SHA-256。测试仅证明调度核心，不证明 Windows 读写或界面已完成。
