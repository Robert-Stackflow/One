## PP-FormulaNet S 与统一预处理

- [固定官方版本](https://huggingface.co/PaddlePaddle/PP-FormulaNet-S/tree/0572450e501be9eb1b1cdb7e00fccf4b22fab4df)，Apache-2.0。权重 231675001 bytes，SHA-256 `b6392296d16e2a9f414c0a751d7ccbd1bd9d8272b68aab72df1d3875f35a7489`；配置、图及固定 URL 见模型目录。输入 `[1,1,384,384]`，上限 1024 tokens，推理/转换提交内存预算为 2048/4096 MiB。
- 原始 opset 19 图为 308743097 bytes，SHA-256 `a588f558afc23177bfdbf533904f5a2e0c02f3065d850d5844de0cf470f7939d`。受控规范化 `If.3` 两个标量输出后为 308743452 bytes，SHA-256 `fa840f4f486dbee62f2ef507fa2871702ab9746d6922024ef641db4ce08a6a69`；受管理运行包重新转换得到相同散列并通过 checker。原始导出约 4 秒、峰值提交 2392 MiB。
- 官方示例 Paddle CPU 约 2 秒、219 tokens；One 原生 CPU 约 1 秒，NVIDIA DirectML 0 约 2.0/1.1 秒，AMD DirectML 1 约 2 秒，两次 token 散列均与 Paddle 相同，实际 GPU 算子执行已核对。受管理工作进程按 CPU → NVIDIA → AMD → CPU 切换通过，实际峰值 RSS 约 974/1028/1015/974 MiB。不改已有公式服务/初始本地型号，按型号分别准备、删除和持久化。
- 五组旧合成样本最初在多行图上发现 sharp 与 Pillow 重采样差异，引起额外识别变化。新增 `formula-resample.ts`，仅在独立公式任务进程中实现 RGB8 定点线性/三次滤波、thumbnail 整数降采样/边缘舍入和 NumPy float32 操作顺序；解码与透明图白色铺底沿用原路径。九组彩色图覆盖横竖比例、奇数边缘、缩小、方图及小图，与 Pillow 12.3.0 / NumPy 黄金张量 SHA-256 完全一致；官方图及五组公式另做逐元素/字节比对，均零差异。RGB 黄金样本预处理约 7–51 ms；官方图约 63 ms。Pillow 移植部分保留 MIT-CMU 许可，构建声明同时补齐此前已捆绑的 MathJax/字体及依赖许可。
- 修正后五组应用结果与 Paddle 一致，四组可通过 KaTeX；分式、矩阵、上下标的表达格式有所不同，不能用字面相等率评价数学正确率。分段样本的结构损坏而无法预览，多行样本第一行漏掉 `a`，两者在 Paddle 中同样存在，属于模型质量缺陷，未通过广泛质量验收。
- 复现：`node tests/formula-preprocess.cjs`、`node tests/formula-model-store.cjs --base --cases`；窗口用 `ONE_FORMULA_FIXTURE_SIZE=base-S node tests/formula-local-window.cjs`（PowerShell 设置对应环境变量）。证据 `work/current/capture-reconstruction/formula/base-s/`、`base-s-*.log` 与 `preprocess/pixel-parity.json`。真实手写/中文/复杂场景仍待验证。

## plus-M 固定版本与应用验证

- [官方源文件](https://huggingface.co/PaddlePaddle/PP-FormulaNet_plus-M/tree/712e6e2e4c313b1ea163be5c350127b82662c58d)，Apache-2.0。权重 617064962 bytes，SHA-256 `f16ef9b5c8227da70d3ec969a5195f4d62c1154427b883f4d6cff07633654041`；图与配置散列固定在 `formula-model-catalog.ts`。输入为 `[1,1,384,384]`，输出上限按官方配置为 2560 tokens，不能沿用 S 的 1024 上限。
- 固定 Paddle 3.1.1 / Paddle2ONNX 2.1.0 / opset 19。4 GiB 转换两种设置均报 `bad allocation`；检查固定版本的 [PIR 导出源码](https://github.com/PaddlePaddle/Paddle2ONNX/blob/c8b5048c3a0903986bd3ec1cce2af9915b391c49/paddle2onnx/mapper/exporter.cc)后确认完整图复制及序列化会同时占用内存，关闭优化不能移除这些副本。导出改用 6144 MiB 硬预算，实测峰值提交内存 4145 MiB，约 6.4 秒退出；后续独立推理限制 4096 MiB，不扩大 S 的预算。上游另有 [PIR 优化/外部数据处理修复提案](https://github.com/PaddlePaddle/Paddle2ONNX/pull/1640)，本项目未引入未验证的导出器版本。
- 原始 ONNX 为 720108668 bytes，SHA-256 `1cad8bae0dc02c17bfb9a56221dba5f26c205180f8b798f0c22fba05e623e94b`。本型号需要规范化的是 `If.7` 的两个 float 标量输出，`If.3` 是注意力分支，禁止复用 S 的节点名。受控修正后为 720109023 bytes，SHA-256 `2787955eda423df7d048926d0269a0e918c1866b31f75c7271d12577b50fa3c0`，通过 ONNX checker；固定转换配方重新构建得到相同散列后才发布缓存。
- 同一官方示例的 Paddle CPU 两次约 8.6/7.6 秒，均输出 199 tokens。One 实际原生 ONNX 的 CPU、NVIDIA DirectML 0、AMD DirectML 1 与 Paddle token 散列和 LaTeX 一致；profiling 确认 DirectML 执行算子，亦有 CPU 算子。应用受管理准备后，独立工作进程按 CPU → NVIDIA → AMD → CPU 切换，耗时约 6.1/7.5/10.5/5.8 秒，峰值 RSS 约 2045/2099/2083/2045 MiB。此例 GPU 没有更快，不以设备支持代表提速或广泛质量通过。
- 缓存按型号独立管理安装、删除及租约，共用转换运行包；旧 S 准备缓存身份保持不变。验证入口 `node tests/formula-model-store.cjs --medium`，元数据/选择隔离见 `node tests/local-model-manager.cjs`。证据 `work/current/capture-reconstruction/formula/plus-m/` 的源 manifest、Paddle/ONNX/预算/受管理运行报告及同级 `plus-m-*.log`。中文、手写、暗色及复杂多行真实质量仍待专项验收，M 不改为默认模型。

## plus-S 固定输入与转换

- 原始权重：[官方仓库固定版本](https://huggingface.co/PaddlePaddle/PP-FormulaNet_plus-S/tree/3d46f557e3a1752f4bf81202395af3b5ecfadfd2)，Apache-2.0。`inference.pdiparams` 为 256845006 bytes，SHA-256 `e464f94412feaa98f8791eacc84684f887b3569e30e80c52b8112e9cf7d4069b`。
- 示例：[官方公式图](https://paddle-model-ecology.bj.bcebos.com/paddlex/imgs/demo_image/general_formula_rec_001.png)，SHA-256 `7885d4a349edcdfbfbc439305b8b554c2500f095949bc53d14835656b902dbcc`。图像按官方裁边、缩放、黑色补边、灰度归一化和 LatexImageFormat 生成 `[1,1,384,384]`；不能把三通道输入再次交给会扩展通道的导出图。
- Python 3.12.7 隔离环境位于 `work/current/capture-reconstruction/formula/.venv`；Paddle 3.3.1 和 3.1.1 均完成两次 CPU 推理。Paddle2ONNX 2.1.0 在 3.3.1 下遇到 DLL 加载失败，改为 3.1.1 后可运行；这是本机验证，不是全部版本的兼容承诺。[上游相同问题的版本说明](https://github.com/PaddlePaddle/Paddle2ONNX/issues/1615#issuecomment-3743495149)。完整依赖冻结见 work 中 `requirements-*.lock.txt`。

- [受保护的标量修正脚本](../../scripts/probes/formula-onnx-scalar.py)仅接受原图 SHA-256 `575353f72a804215329b128ed1b85e8de65fdb4b06730ac8e7954bae5c44e64d`，在两个已声明为标量 FLOAT 的 If.3 分支末尾增加显式 Reshape，不改权重或数值。输出 SHA-256 固定为 `bf3ecd1f6dcc2cdffdcad7421f44585df3578501f5552ed5122351c2e241c835`，通过 ONNX checker 与重新生成的一致性检查；它不是通用修复器。

## 本机结果与边界

One 使用的 `onnxruntime-node` 1.30.0 直接加载修正图；CPU、DXGI 0（NVIDIA RTX 4060 Laptop GPU）和 DXGI 1（AMD 610M）每个后端两次推理，均返回 201 个 token。序列 SHA-256 全部为 `dfe5946933c02dd9f6345cb6ec30936c64b6463ce8678d9992f383e4f62c51a3`，与 Paddle 3.1.1 的序列一致；原生 ByteLevel 解码后的 LaTeX 相同，KaTeX 可解析。

| 独立原型运行 | 模型加载 ms | 首次/再次推理 ms | 进程峰值 RSS MiB |
| --- | --- | --- | --- |
| Paddle 3.3.1 CPU | 1807 | 2205 / 2047 | 570 |
| Paddle 3.1.1 CPU | 1723 | 2000 / 1813 | 563 |
| Python ONNX 1.31 CPU | 1394 | 679 / 675 | 767 |
| One Node ONNX CPU | 900 | 833 / 934 | 997 |
| One Node ONNX DirectML 0 | 1295 | 2028 / 941 | 1059 |
| One Node ONNX DirectML 1 | 1256 | 1935 / 1717 | 1028 |

最后一次 CPU token 严格校验与图文件散列并行运行，耗时 1301/1461ms；不把该次负载差异解释为模型质量或固定延迟。DirectML 原生事件分别记录 29964 次 GPU 与 28144 次 CPU 算子事件，确认有 GPU 执行，也不能宣传整图全部在 GPU 上或稳定更快。显存峰值尚未测量。这一官方印刷公式示例不证明矩阵、分段、多行、中文、手写、暗色或真实截图质量门槛通过。

当前以 CPU 作为 plus-S 默认后端候选，最终决定仍随完整样本和应用资源预算核验。转换后的模型超过现有 OCR 工作进程的 256 MiB 单文件限制；接入时需要独立公式任务契约及合理预算，不能直接解除 OCR 的既有边界。

## 可复现入口

1. 使用 `hf download PaddlePaddle/PP-FormulaNet_plus-S --revision 3d46f557e3a1752f4bf81202395af3b5ecfadfd2 --local-dir <work目录>` 取得固定文件；无需登录，下载时关闭隐式 token 使用。plus-S/M 已取得固定源文件；其他型号仍按实际原型需要下载。
2. 在隔离的锁定环境中执行 [Paddle/ONNX CPU 探针](../../scripts/probes/formula-runtime.py)，必填 `--model-root`、`--image`、`--report`；ONNX 路线另传 `--onnx`。图像、权重、token 散列及资源记录写入 report。
3. 使用上述导出参数，然后执行标量修正脚本的 `--source`、`--output`。保留原始导出图，已有相同输出不重新写入。
4. [One 原生 ONNX 探针](../../scripts/probes/formula-onnx-runtime.cjs)接收 `--model`、`--sha256`、`--tensor`、`--config`、`--reference`、`--report`，支持 `--backend cpu/dml --device 0/1`。tensor 是 CPU 探针 `preprocess()` 返回的连续 float32 字节；reference 必须包含 Paddle 的 token SHA-256。每次使用新的 profiling 前缀，GPU 探针要求实际 GPU 事件，不能用旧日志冒充。

证据保留在 `work/current/capture-reconstruction/formula/`：官方版本元数据、权重、源图、依赖锁、原始/修正 ONNX、`plus-S-*.json/.log`、`scalar-repro.log`、原生设备映射和 profiling。安装准备、失败/取消、CPU 回退、设备/模型切换、独立窗口与退出已验证；其他完整模型家族继续作为交付项。

## 独立公式任务运行层

`formula-local-runner.ts` / `formula-local-worker.ts` 已加入运行层、worker 构建入口及独立公式 IPC/模型选择窗口。每个运行器拥有独立进程与热缓存；复用全局本地推理队列，切换任务所属运行器前卸载旧缓存。原图与模型身份冻结，回包必须匹配图片 SHA-256、模型/版本和后端；输入、设备或预算变化不能混用旧任务。Windows Job Object 按预设限制进程提交内存（S 为 2048 MiB，M 为 4096 MiB），并在关闭句柄时结束进程；另采样 RSS。它不限制显存。取消、超时、错误和关闭等到实际进程退出才交还调度；仅自动模式允许同模型 CPU 回退，强制 GPU 错误不冒充 CPU 成功。

模型和字典按尺寸/SHA-256读取校验后的字节，拒绝文件链接，不在运行时再次按可变化路径加载。当前仅接纳已验证的 PP-FormulaNet S 及 plus-S/M 图，并逐项匹配型号、源版本、配置和输出散列。预处理和推理都在子进程：PNG ≤8 MiB、解码 ≤4194304 像素、放大中间图 ≤8388608 像素；裁去空白后按 384 输入缩放/灰度归一化/补边。图片解码仍使用 sharp，公式 RGB 两阶段重采样、thumbnail 降采样及 float32 运算顺序已按 Pillow 固定实现移植；官方图、下列五组公式及九组 RGB 黄金测试的最终张量逐字节匹配参考。空白或过于狭长区域明确拒绝并保留输入。

按官方 `UniMERNetDecode.token2str`，只解码首次 EOS（2）及之前的 token；后续并行生成的尾部内容不属于公式。原型探针也已同步，raw token SHA-256仍记录完整模型输出。没有 EOS、字典/编码错误或无效字符不会交付假结果；不通过删除合法区间内的反斜杠“修正”模型。LaTeX 解析/语义质量仍独立验收。

`node tests/formula-local-runtime.cjs` 验证输入冻结、错误回包、GPU 回退/强制失败、取消、超时、硬内存限额、排队取消、其他任务启动前缓存卸载、实际 PID 退出、EOS/未知 token、空白输入；`--runtime` 使用既有固定模型检查真实 PNG→CPU 冷热识别，`--gpu` 检查 CPU→NVIDIA→AMD→CPU 切换，均不下载模型。`node tests/formula-case-images.cjs` 用本地 KaTeX 字体生成固定合成 PNG；`--runtime --cases` 记录逐个原文/识别文字及预览错误，不把语义错误当作后端失败藏掉。

| 合成样本 | 与 Paddle EOS 解码一致 | 本轮文字/结构观察 |
| --- | --- | --- |
| 分式/根式 | 是 | 主要表达式一致 |
| 矩阵 | 是 | 四项与括号保留，输出采用 matrix/left/right 结构 |
| 分段 | 是 | 条件与分段文字保留，但左括号有冗余 |
| 上下标/求和 | 是 | 主要表达式一致 |
| 多行 | 是 | 首行出现额外 c 与逗号，质量未通过 |

所有五组经 EOS 截断后可被 KaTeX 解析；这并不消除上述模型质量问题。样本是合成印刷公式，手写/中文/暗色/透明图和广泛真实截图仍待测，plus-S 尚不提升为默认公式模型。证据：`formula/local-{types,bundle,runtime,runtime-cases,runtime-gpu}*.log`、`local-case-results.json`、`cases/*-paddle-eos.json`、`local-runtime-result.json`。
## 按需准备的独立运行包

`FormulaRuntimeStore` 已实现 Windows x64 的嵌入式解释器与依赖缓存，已由公式模型目录的准备操作接入；打开模型弹窗不触发运行包安装或模型加载。解释器固定为 CPython 3.12.7 embeddable，Paddle 3.1.1、Paddle2ONNX 2.1.0、ONNX 1.17.0 等 18 个 wheel 使用实际版本、官方下载 URL、大小与 SHA-256；`packaging` 是转换入口的动态依赖，已显式纳入清单，不能只依赖发行包的依赖元数据。共 19 个压缩包，约 148 MiB；展开 12151 个文件、约 499 MiB。原始 archive 与展开目录分别管理，不要求安装到系统 Python，也不把这套依赖强行加入全部用户的安装器。

默认 `_pth` 仅指向解释器自身和自己的 `Lib/site-packages`；执行使用 `-B`、`PYTHONDONTWRITEBYTECODE=1`，转换禁用第三方自动安装依赖。私有目录以 One/formula-runtime/schema/版本标记识别；展开清单的 SHA-256 固定为 `508ca25b01e805ffb403a9ff2c24e852ff2bd84a7267e5d4c2f8a1c19d2dd569`。准备时以已校验 archive 构造文件清单，匹配全部名称/大小/内容散列后才原子发布；仅看 archive 安装完成不能执行解释器。读取运行包状态只看小型元数据，取得使用租约时校验完整文件树，不加载推理模型。

解压拒绝越界、非法 Windows 名称、加密、链接、重复/大小写冲突和超限内容；解压、文件验证和临时目录回收可以取消。多个准备调用共享任务，各自取消互不影响，最后一个调用取消才终止准备；重试等待旧准备清理完毕。运行包使用中不能删除/覆盖；准备失败保留旧目录和已缓存 archive。删除拒绝外来文件和链接，未知归属目录保留。静默丢弃用户笔记或清除整个 models/work 目录不是修复策略。

## 权重到本机模型的受管理准备

`formula-model-catalog.ts` 固定 PP-FormulaNet S 与 plus-S/M 的官方 `inference.json`、`inference.pdiparams`、`config.json` URL、大小与散列。没有为本机生成的 ONNX 虚构下载地址。`FormulaModels` 按型号分派独立 `FormulaModelStore`，组合原始权重缓存、独立 `FormulaRuntimeStore`、受控转换和 native 模型租约；当前为已验证的 PP-FormulaNet S 与 plus-S/M 注册公式模型弹窗，默认仍保留视觉服务来源；其他家族及尺寸继续适配。

`formula-model-builder.ts` 只运行应用内固定的转换脚本和参数。转换进程使用共享本地任务队列，在其他保留的推理模型卸载后开始；Windows Job 按预设限制转换提交内存（S 为 4096 MiB，M 为 6144 MiB），超时 300 秒，取消等待实际 `close` 后释放资源。禁止依赖自动安装，不使用系统 Python 配置；固定 Paddle2ONNX 导出散列和两分支标量约束，S 的最终 ONNX 仍为 `bf3ecd...`，M 为 `278795...`。

准备先保存并校验官方源文件，取得运行包租约，在专属临时目录生成 ONNX；原始权重不修改。输出 ONNX 与配置逐项验证内容散列后，按权重、配方、运行包版本的身份原子发布。界面状态查询只读取目录、小归属记录和文件元数据；真正执行前的 `acquire` 重新验证内容。已有有效 native 缓存不再启动转换或准备运行包。缓存使用期间禁止覆盖/删除；源权重与生成缓存存在外来文件或链接时拒绝替换/删除。共享准备只启动一次，最后一个请求取消后等转换/临时目录清理；运行包独立保留，不随单个模型删除。

## 公式窗口与模型选择

PP-FormulaNet S 与 plus-S/M 已进入 `LocalModelManager` 的 `formula` 目录，公式 preload/IPC 仅允许本窗口模型，OCR 弹窗仍只展示 OCR。公式窗口顶部选择视觉服务或本地模型；默认保持已有视觉服务，使用本地模型后显示当前模型。模型弹窗复用 One 左右结构，侧栏标记“使用中”，删除位于标题栏，使用后关闭。权重与首次准备的共享运行包分别列出体积，总下载进度覆盖两者；准备阶段只有取消操作，不显示虚假的转换百分比。自动设备固定 CPU，只有显式选择 GPU 才读取显卡。

同一数据目录下的模型设置共享加载结果、修订号与保存锁，OCR、背景修复、公式及上次本地公式设备保存在原设置文件中。两个窗口交替保存不会覆盖另一方选择；切换到视觉服务保留本地选择，再切回可直接恢复。首次打开模型弹窗先显示外壳，后台只读元数据，不执行推理。点击识别后才取得校验租约并进入独立进程/共享任务队列；选择、图片和返回结果严格对应，强制 GPU 失败不冒充 CPU 成功。结束任务后释放租约，删除时卸载保留的本机缓存，关闭 OCR 不取消公式任务。

## 区域裁剪与公式图片输出

画布裁剪复用图片坐标/旋转映射，按原像素提取并应用当前旋转；每次替换更新窗口 token，旧资源与请求失效。恢复原图还原原始 PNG 字节，两者均保留手工 LaTeX。未裁剪时识别也实际使用当前旋转。单次区域最多 400 万像素，结果最多 8 MiB；原图独立保留，关闭窗口清理。

复制图片与导出菜单提供 PNG/SVG。以现有 KaTeX 安全规则生成 MathML，再由独立进程内的 MathJax 4.1.3 和内置 TeX 字形生成 SVG，PNG 从相同矢量结果生成。不接收 renderer 提供的 SVG，不启用 TeX 动态扩展、外部图像或网络字体。数学字形使用本地路径缓存，未覆盖的 Unicode 文本保留 SVG 文本，可能依赖接收端系统字体；不宣称全部中文均转为轮廓。依据 [官方 Node 直接调用](https://docs.mathjax.org/en/latest/server/direct.html) 与 [SVG 本地缓存](https://docs.mathjax.org/en/v4.0/options/output/svg.html)。

工作进程使用共享队列，768 MiB Windows 进程提交上限、128 MiB V8 堆、15 秒超时和有界 Sharp 缓存，取消等待子进程退出。输出限 5 MiB SVG、800 万像素/8 MiB PNG、边长 16384；失败保留 LaTeX。保存使用路径保护与同目录原子提交，取消不覆盖已有文件，窗口关闭后的迟到导出不落盘。

`tests/formula-image.cjs` 验证分式、矩阵、分段、上下标、多行、Unicode 保留、禁止额外数学模块加载、危险输入拒绝、四向精确裁剪及取消退出；`tests/formula-image-window.cjs` 在真实 One 验证菜单、剪贴板、SVG 路径、取消保存、旋转框选、原图字节还原、文字保留和关闭后拒绝保存。旋转夹具实际送入 CPU/DirectML 后结果一致。OCR 框选/取消、36000 字形层、Markdown 实窗、123 项业务和类型/JS 构建通过；证据 `formula/image-*.log`、`export-*.log`。
