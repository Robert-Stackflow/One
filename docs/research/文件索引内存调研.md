# 文件索引内存与驻留

## 当前实现

约 431 万条真实记录的压缩快照约 79 MiB，加载成可修改的索引对象后，原生辅助进程私有提交约 923 MiB、工作集约 905 MiB。占用来自记录、排序结构、路径、匹配摘要及拼音等数据，并非磁盘缓存本身有 900 MiB。已有目录前缀共享与路径拼写压缩，仍不能消除每条记录的对象开销。

目前辅助进程启动时恢复完整索引，闲置期间保留它，以便检索、目录变化与增量验证复用。整份展开数据并非必须常驻；只保留目录监听、少量增量和查询缓存也能实现后台服务。直接闲置卸载当前对象会导致再次搜索重新恢复快照，同机实测约 5–7 秒，不能把它当成无代价的解决方法。

## 只读磁盘原型

原型与可修改索引共用查询解析、类型过滤、匹配分数、拼音与模糊匹配、目录优先级。独立诊断入口 `mapped-build` 只用于把验证副本转换为不可变镜像；`mapped-query` 每次查询映射只读镜像，返回前解除映射。活动应用没有启用这条路径，也不迁移用户缓存。

镜像按排序后的路径保存固定记录表，目录前缀共享，文字用相对偏移读取。可能性摘要与类型先过滤，再检查文字和拼音，避免对全部记录进行文字解码。当前目录通过二分查找直接定位子树，先交付局部结果，再扫描全局并合并前 100 项。

映射只允许读取，文件句柄拒绝同时写入；解析检查头部、节长度、偏移、UTF-8 和拼音数量。没有把 Rust 对象或指针直接持久化。接口依据：[CreateFileMappingW](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-createfilemappingw)、[MapViewOfFile](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile)。

## 本机测量

固定验证 `mapped-index-performance` 使用同一份真实快照与增量日志的副本，关闭副本的扫描根目录，活动应用的配置及数据不变。原版、共用匹配代码的普通索引、磁盘原型分别使用新进程，每条查询重复两次，比较命中总数和全部前 100 项路径、名称、元数据、匹配类型。19 个条件包含拼音、模糊、引号、路径、类型、目录优先级及当前目录；全部结果一致。普通引擎的程序／设置过滤回归也通过，但磁盘原型尚未实现程序／设置混排。

最新样本为 4,315,595 条记录：

| 项目 | 可修改内存索引 | 只读磁盘原型 |
| --- | --- | --- |
| 闲置私有提交 | 约 923 MiB | 约 1.26 MiB |
| 闲置工作集 | 约 905 MiB | 约 5.02 MiB |
| 磁盘数据 | 压缩快照约 79 MiB | 未压缩镜像约 500 MiB |
| 仅恢复／打开索引 | 约 6.59 秒 | 约 31 ms |

原型镜像生成约 8.57 秒，仍先恢复旧快照，因此生成阶段没有解决高内存问题。31 ms 仅为打开已生成镜像，不包含首次转换、目录验证或监听初始化。

摘要预过滤后的全局查询墙钟约 0.15–1.01 秒，当前目录部分约 5–6 ms。与同轮普通引擎相比，有些查询更快，有些较慢：无结果约 252 → 150 ms，QQ 约 444 → 292 ms；广泛路径约 350 → 665 ms，拼写容错约 744 → 1,009 ms。测试按进程顺序执行，负载和调度存在波动，不能宣称固定速度收益。

解除映射后的空闲内存很低，但搜索中工作集峰值约 503 MiB；磁盘页还可能留在 Windows 文件缓存中，并非整个系统只使用 1 MiB。磁盘缓存因镜像刚生成而较热，本实验不代表重启后的冷存储读取。未通过强制清空工作集、减少记录或减少返回结果制造降幅。

首次原型没有摘要预过滤，全局查询约 0.55–0.98 秒，少命中场景明显较慢。两次实验的原始结果保留于有上限的验证目录，快照副本、镜像和测试配置结束后清理。

## 接入前仍需完成

这不是运行版的内存修复。还需支持增量修改与删除、目录验证、后台合并、快照校验与损坏恢复、版本迁移、独立查询取消及程序／设置混排。首次生成也需要流式构建，不能依赖恢复整份高内存索引。

更合适的生命周期是磁盘索引持久化，搜索活跃期间保留必要读取和有上限的缓存，闲置后释放大数据视图，仅保留轻量监听和增量。正式接入前应验证实际后台负载、连续输入、冷存储响应、文件变更及内存上限。
