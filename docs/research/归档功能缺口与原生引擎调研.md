## 可复用的原生实现

### 优先扩展现有 7-Zip C++ 引擎

One 当前实际打包的 `vendor/archive/7zip/7z.dll` 文件版本为 **26.04**；原始安装器、DLL 与当前来源已在 `vendor/archive/SOURCES.txt` 记录。现由固定提交源码加独立 ZIP 密码编码补丁构建；完整对应源码、补丁和构建说明位于 `vendor/archive/7zip/`，当前二进制哈希见 `verification/archive-zipx-password/latest.json`。独立的 `One.Archive.exe` 已通过 7-Zip 接口执行读取任务，优先复用现有隔离、资源预算、路径防护、进度和取消协议。

[7-Zip 官方格式列表](https://www.7-zip.org/)列出 BZIP2、WIM 的读写，以及 CAB、ISO、LZH 等只读格式；对应 [C++ 源码](https://github.com/ip7z/7zip/tree/main/CPP/7zip/Archive)还包含 ZIP、BZip2、Cab、Iso、Lzh、Wim、Zstd 处理器。Zstd 代码包含受构建宏控制的输出接口，不能仅凭源码存在断言当前 DLL 可创建 ZSTD；应查询实际 DLL 的处理器属性并用真实文件验证。

建议首批接通：CAB、ISO、LHA/LZH、WIM 只读，BZ2/ZSTD 单流读取及已验证的 TAR 组合。WIM 创建、镜像选择和增量/分割 WIM 另列范围，不由读取支持自动开放写入。ISO 需覆盖 Joliet、Rock Ridge 或 UDF 的实际能力；ZSTD 需区分普通帧、拼接帧、skippable frame 与需要字典的文件。

ZIPX 仍是 ZIP 家族容器，但内部方法可能不同。应按真实方法验证后开放只读，保留“方法不支持”的错误，不把 ZIPX 改名为 ZIP 就视为支持。JAR/APK 可复用 ZIP 读取；默认只读，修改可能破坏签名或应用包语义。

7-Zip 大部分代码使用 LGPL，部分 BSD，RAR 解码部分有 unRAR 限制，按项目现有分发方式保留声明和对应源码来源。以[官方许可](https://github.com/ip7z/7zip/blob/main/DOC/License.txt)为准。

### libarchive：C 库，可由 C++ 调用

[libarchive 官方 README](https://github.com/libarchive/libarchive)明确列出 ZIPX 的 bzip2、zstd、ppmd8、lzma、xz 方法，以及 CAB、LHA/LZH、ISO9660 和 ZSTD/BZIP2 过滤器。主体为 BSD 风格许可，个别文件和依赖另有条款，见 [COPYING](https://github.com/libarchive/libarchive/blob/master/COPYING)。

它适合流式解码和作为特定缺失方法的补充，但不直接支持原位更新或随机访问。对 One 已有的分页浏览、包内修改和恢复协议，额外引入第二套引擎有维护成本；先验证现有 7-Zip 的缺口，再决定是否增加它。它也不应被视为 ALZ/EGG/WIM 的通用替代。

### ALZ：已接入受限单卷读取

已固定 [Debian UnAlz 0.65 原始包](https://deb.debian.org/debian/pool/main/u/unalz/unalz_0.65.orig.tar.gz)，SHA256 `4c26699eb7545072de2ef7de79b4fff1f01c4db09cebff2d8d50ec03d5d74db0`，与 Debian 源包描述中的大小及哈希核对。Kippler 的 zlib 许可已保留。审阅发现旧解析器存在长度、偏移、未检查读取和名称截断问题，因此产品使用新的有界目录解析器，不接入旧路径写入器或旧捆绑依赖。

DLZ 采用 [bzip2 1.0.8](https://deb.debian.org/debian/pool/main/b/bzip2/bzip2_1.0.8.orig.tar.gz) 的最小帧头修改，保留较新解码边界检查；固定哈希、原许可及逐行补丁见 `vendor/archive/alz-bzip2/`。DLZ 无内部 BZip2 CRC，必须核对外层 ALZ CRC32 与精确长度。标准 BZh 模式保留原 CRC 验证；现有 `.bz2` 仍走 7-Zip。

v10 单卷及分卷、存储/Deflate/BZip2-DLZ、加密和 CP949/UTF-8 已有固定样本、独立参考解码及产品流程验证，见[ALZ 样本说明](../../tests/fixtures/archives/alz/README.txt)和[分卷样本与独立核对](../../tests/fixtures/archives/alz-split/README.txt)。分卷逐卷校验顺序号及首尾框架，通过 11 个外部卷、14 个文件的独立 Store/Deflate CRC/哈希核对，其他已验证编码流按任意边界拆分后继续通过；从后续卷打开、全组版本绑定、缺卷/损坏拒绝发布及 a99/b00 转换已覆盖。数据描述符和其他版本仍待验收；未知组合明确拒绝。EGG 不随本次 ALZ 支持自动开放。

### EGG：采用独立 MIT 参考，C++ 产品接入已完成

ESTsoft UnEGG 的 [C++ 源码镜像](https://github.com/dterracino/UnEgg)提供 EGG/ALZ 解码参考；其[原始许可](https://github.com/dterracino/UnEgg/blob/master/Source/unegg/doc/license.txt)明确要求商业用途获得公司批准，并限制 AZO 算法修改等行为。不能只因可下载源码，就作为无条件可分发的开源依赖接入 One。

新核对的 [EggDotNet](https://github.com/akolman/EggDotNet/tree/78b64f54026a8687dac1cdd4c86eb5fe5abf04ae) 作者声明采用 [MIT 许可](https://github.com/akolman/EggDotNet/blob/78b64f54026a8687dac1cdd4c86eb5fe5abf04ae/LICENSE.txt)。已固定其完整 C# 库源码及真实样本，构建独立验证程序，实际解码并验证 CRC 的 22 个数据集，覆盖 Store/Deflate/BZip2/LZMA/AZO、AES/ZipCrypto/LEA、非英文文件名、前置内容加密参数、固实和两卷文件；源码、样本哈希和许可见[参考样本说明](../../tests/fixtures/archives/egg/README.txt)。C++ AZO 模块已通过 5 个外部文件的输出哈希及 377 项边界/资源检查；容器读取器另通过 374 项目录、多块/固实和分卷检查，属性样本的五项元数据也可读取，5 方法解码、逐块 CRC 和 AES/LEA/ZipCrypto 另通过 195 项检查，25 个真实数据集可正确解码；产品适配层已接通浏览、详情、校验、选择解压、预览、拖出和命令行，逐文件哈希、固实选择及从后续卷打开通过验证。`.NET` 仅用于验证，不进入 One 运行依赖；产品仍沿用 C++ 路径。

参考实现不能直接视为产品完成：它注明逐项只保留一个压缩块；`extattr.egg` 触发空引用，两个 15 字节 LEA 文件返回全零但长度相符，现由独立 CRC 检查识别为参考解码缺陷；197540460 字节的高压缩比样本被验证程序的 64 MiB 输出上限中止。C++ 核心已独立完成有界目录、分卷关联、多块读取、逐块 CRC、精确长度和内容认证；产品复用既有路径预检、风险、资源、磁盘余量和暂存发布机制；同族分卷全部绑定版本，变更后拒绝使用旧选择，认证或 CRC 失败不发布内容。核心明确拒绝加密文件名和加密固实流；父路径标志仅记录原始字段，真实写入语义尚待核对，不能仅凭合成结构样本宣布兼容。已开放上述只读产品入口；真实 AZO x86 过滤和更多写入器变体仍待验证。

### 其他候选

[bit7z](https://github.com/rikyoz/bit7z) 是现成 C++ 的 7-Zip 动态库封装，当前 4.x 使用 MPL-2.0；它不会增加底层 DLL 的格式能力。One 已有适配层，不建议仅为更多格式重新替换接口。

[官方 libzstd](https://github.com/facebook/zstd) 是可由 C++ 调用的 C 实现，采用 BSD/GPL 双许可选择，适合独立 `.zst` 及 TAR.ZST 的流式读写。若现有 DLL 的实际 ZSTD 写入能力不足，可评估此小范围补充，而不是为所有格式重建引擎。

## 接入顺序与完成标准

1. 查询当前 DLL 的真实处理器及输入/输出能力，先做 CAB、BZ2、ZSTD、LHA/LZH、ISO/WIM 只读原型。
2. 每种格式使用独立工具生成或上游真实样本；检查列表、选中项解压、全量解压、完整性、错误方法、坏包、路径防护、取消、资源不足与源变化。比对解压内容哈希。
3. 同步原生分派、服务校验、共享能力表、GUI/CLI、系统入口和用户指南。读取、创建、修改、分卷、加密分别开放。
4. JAR/APK 和已通过方法矩阵的 ZIPX 接只读入口；签名容器不默认修改。
5. ALZ 已接入受控单卷读取，继续验收分卷与变体；EGG 待许可与实现选型结论明确。
6. 独立补齐大规模基准、真实外部编辑器、拖出目标和安装版验证。库支持格式不代替这些验收。
