# 预览格式支持与体验调研

2026-10-10。按用户要求，数据库预览整体延期，当前先评估已有格式，优先 XLSX，再看 DOCX、PPT/PPTX。本轮只完成调研与样本核验，没有修改预览引擎。用户后续指定 XLSX 采用原生展示，不继续扩展自绘表格。

## 结论与顺序

XLSX 目前更接近数据摘录器，既缺少表格排版，也存在数字显示错误；应优先更换展示路径。DOCX 的主要短板是分页与字体保真。PPTX 的短板包含实际内容遗漏，不能只调整页面样式。旧 `.ppt` 尚未支持，与 `.pptx` 渲染不完整是两个问题。

建议顺序：XLSX 原生预览接入与失败处理 → DOCX 分页/字体和 PPTX 内容遗漏 → CSV、EPUB 等日常体验补强。PDF、图片、文本已有较完整的阅读交互，本轮没有发现需要抢占 Office 优先级的新证据；这不代表已经完成它们全部格式变体的实测。

## 调研范围与证据

- 检查格式路由、解析模型、渲染和释放调用链，以及现有测试的覆盖目标。入口是 `src/main/preview-service.ts`，展示入口是 `src/renderer/preview-view.ts`。
- 生成自有 XLSX 样本，直接运行当前 `src/main/workbook.ts`；生成 DOCX、PPTX 样本，在隔离配置的真实 Electron 预览窗口核验。样本及报告位于 `work/current/preview-research/`，包括 `audit.cjs`、`ui-audit.cjs`、`parser-report.json`、`ui-report.json`。
- 本轮未使用真实业务文件，也未逐页与 Microsoft Office 输出对比。以下区分样本实测、源码确认和待实测风险；不把源码推断写成全部文档必然出错。
- Office 归档预检在 Worker 中进行，有大小限制和 15 秒超时；这不等于 DOCX/PPTX 后续在页面中的全部解析与排版都有相同超时保护。

## XLSX：最优先更换展示路径

### 样本实测

| 场景 | 文件中设置/预期 | 当前结果 | 影响 |
| --- | --- | --- | --- |
| 纯时间 | 数值 `0.5`，内置格式 20，应显示 `12:00` | `1899-12-31 12:00:00` | 时间混入无意义日期 |
| 金额 | `1234.5`，`$#,##0.00`，应显示 `$1,234.50` | `1234.5` | 币种和小数位丢失 |
| 自定义百分比 | `0.125`，`0.0%`，应显示 `12.5%` | `12.50%` | 未按格式指定精度展示 |
| 补零编号 | `123`，`000000`，应显示 `000123` | `123` | 编号含义和复制结果可能改变 |
| 1904 日期系统 | `date1904="true"`，日期序号 0 | `1899-12-31`，应为 `1904-01-01` | 将合法布尔值误当作关闭 |
| 公式没有缓存值 | `SUM(1,2)`，无 `<v>` | 单元格为空，点击后才可见公式 | 无法区分空值与尚未计算 |
| 共享公式 | A2 为公式起点，A3 引用同一共享公式 | A3 缓存值保留，公式字段丢失 | 公式查看不完整 |
| 隐藏与空行 | 隐藏工作表、隐藏第 3 行、空第 4 行 | 隐藏内容仍列出；空行省略，行号跳跃 | 不符合原工作簿的阅读结构 |

数字格式的依据见 [Microsoft NumberingFormat](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.numberingformat)，日期系统属性定义见 [WorkbookProperties.Date1904](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.workbookproperties.date1904)。本轮测试直接比较格式语义，没有声称已与 Excel 截图逐像素对照。

### 源码确认的结构与交互缺口

`src/shared/workbook.ts` 只传递表名、行号、列号、文字、公式和截断标记。合并单元格、字体/字号、填充色、边框、对齐、行高列宽、图片/图表、冻结窗格、隐藏状态等没有进入展示模型。因此，复杂表头、财务表、排班表和图文表格会明显偏离原文件，单改 CSS 无法解决。

`src/renderer/special-preview.ts` 使用普通 HTML 表格，每页 100 行。工作表以下拉切换，筛选是文字匹配；缺少名称框跳转、方向键移动、范围选择和列宽调整。每个单元格都进入 Tab 顺序，满宽页可能产生 20,000 个可聚焦单元格；这是结构上的风险，本轮没有测量该极限场景的卡顿时间。

当前上限为 100 个表、每表 20,000 行/200 列、全书 100,000 单元格/400 万字符。已有密集工作簿测试关注行数、翻页、过滤、内存及释放，不覆盖上述格式语义、合并表头或 Office 视觉一致性。单元格文字/公式还会被裁到 32,768 字符，不能把读取成功理解为完整无损呈现。

### 用户指定方向：Windows 原生展示

按在 One 窗口内承载 Windows 注册的 Excel/WPS 预览组件设计，停止给自绘表格继续加排版功能。Windows 的 `IPreviewHandler` 可承载轻量只读预览，不需要打开完整关联应用；微软要求处理器在进程外运行。采用该标准接口，与直接启动 Excel/WPS 是两种不同体验。[微软架构说明](https://learn.microsoft.com/en-us/windows/win32/shell/preview-handlers)、[IPreviewHandler 接口](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ipreviewhandler)。

接入方案应包含：

1. 通过系统关联发现处理器，核验 COM 类实际可用及 32/64 位兼容，不能硬编码 Excel/WPS 路径或只检查后缀注册项。
2. 独立原生宿主承载预览，主进程控制窗口区域、缩放、焦点和生命周期；优先只读流初始化，按组件能力回退到文件/项目初始化。组件初始化卡住时，能取消并结束自己的宿主；不终止共享 `prevhost.exe` 或用户正在使用的 Office。
3. 切换文件、关闭预览、组件崩溃后释放 COM 对象、流和文件占用；防止迟到结果覆盖新文件。验证多 DPI、窗口缩放、键盘操作和不同主题。
4. 无可用组件、位数不匹配或加载失败时，在原预览窗口明确提示，并保留“用默认程序打开”。不悄悄退回用户已否定的自绘表格，不上传文件，也不自动安装/修复 Office。
5. 先以 `.xlsx` 为明确接入范围；`.xlsm`、`.xltx`、`.ods` 和旧 `.xls` 分别检查处理器支持，不能因某一个后缀可用就宣称全部覆盖。原生组件的工作表切换、搜索和图表能力须实测，不预先承诺与完整 Excel 一致。

本机只读检查发现 `.xlsx` 等关联指向 WPS 预览 CLSID，但对应 COM 类在 32 位、64 位注册视图均不存在。这说明有残留关联，尚不能认定原生预览可用。本轮没有安装或修复 WPS，也没有完成原生嵌入；后续实施必须覆盖“有组件”和“缺组件”两种环境。

不优先走 Excel COM 自动化编辑器嵌入、在线 Office 服务或继续扩充自绘网格：它们分别涉及完整应用生命周期/授权、文件上传，或违背本次用户选择。原生方案的取舍是依赖本机已安装且可用的处理器，实际保真度也受该处理器影响。

## DOCX：分页和字体是主要问题

实测：120 个普通段落、没有显式分页标记的 DOCX，被展示为 **1 张超长纸页**，纸页高 2,784 CSS 像素；120 段均存在，本次未出现正文裁切。分页概览因此不等同于 Word 的分页。

上游 `docx-preview` 依赖手动分页、编辑器保存的分页标记和页面设置变化，不提供实时自动分页；字段计算及 TOC 字段也有边界。One 已启用已有分页标记，仍不能把 `breakPages: true` 当作 Word 排版引擎。[docxjs 官方说明](https://github.com/VolodymyrBaydalka/docxjs#readme)。

源码另确认：One 设置 `ignoreFonts: true`，不加载文档嵌入字体；字体替代可能改变换行与分页。注释与 AltChunk 被关闭，链接移除；这些是现有静态预览边界，不能简单恢复全部主动内容来“提高兼容”。页面还设置 `overflow: hidden`，复杂定高内容是否裁切需要真实样本验证，本轮不据此宣称已经丢文。

建议验收集合：长文自动分页、目录/编号、页眉页脚、横竖混排、跨页表格、浮动图片、脚注、嵌入字体。先保证完整可读和明确分页边界，再评估沿用现有引擎的限度或复用原生组件；当前用户仅明确指定 XLSX 原生展示，没有自动将全部 Office 格式改为原生。

## PPT/PPTX：存在内容遗漏

实测：同一 PPTX 页包含一个普通文字形状和一个组合内文字形状，前者显示，后者完全不在渲染结果中。不是仅位置不准确。

`src/renderer/office-view.ts` 仅遍历顶层 `sp`、`pic`、`graphicFrame`，不递归处理 `grpSp`；布局页用于占位符几何回退，却未作为完整的独立图层绘制。主题固定读取 `theme1.xml`，表格主要提取文字；非表格图形框统一显示“嵌入对象”。因此组合图形、布局装饰、图表、SmartArt、复杂表格/文本继承均存在缺口；除组合遗漏外，本轮未对每一类分别生成实测样本。母版和布局是 OOXML 的实际结构，不能当作可忽略的装饰。[微软母版说明](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-slide-masters)。

已有可见页懒绘制和远页回收，应保留这些性能机制。后续优先解决静态内容完整性、布局/主题继承及清晰的降级提示；动画和转场可继续放后面。旧二进制 `.ppt` 当前不进入 PPTX 渲染器，应明确显示不支持或另行评估原生处理器，不能改扩展名后尝试当 ZIP 读取。

## 其他格式巡检

以下以当前源码与支持矩阵为依据，未重新全量运行各格式测试。能力限制不自动等于缺陷，按日常使用影响排序。

| 格式 | 当前较完整的部分 | 短板/后续验证重点 | 优先级 |
| --- | --- | --- | --- |
| 文本/代码 | 大文本 Worker 解码、虚拟化、查找和高亮 | 无 BOM 的传统编码识别和错误后恢复需按实际文件验证；不盲目扩大体积上限 | P2 |
| Markdown | GFM、源码切换、目录、本地图片 | 5 MB 渲染界限；MDX 不执行组件。复杂数学/图示不在已承诺范围 | P2 |
| HTML | 隔离静态排版、本地 CSS/图片 | 不执行脚本/联网；CSS 相对资源不递归改写，依赖资源的页面可能不完整 | P2 |
| JSON/YAML | 源码、结构树、路径复制、按需节点 | 结构视图 5 MB 限制；大文件降级后保持定位/查找体验 | P2 |
| CSV/TSV | 引号/多行解析、虚拟滚动、单元格定位 | 表格视图仅 5 MB；日常大 CSV 会降级源码，应优先评估有界流式表格 | P2 |
| 图片 | 常见图片、缩放/平移/适应、EXIF | RAW/HEIC 等未列支持；超大像素和动画内存需按样本测量，文件大小不是唯一成本 | P3 |
| 音视频 | 自绘播放条、歌词、封面、元数据 | 扩展名不能保证内部编码可播放；当前失败提示依赖默认程序打开 | P2 |
| PDF | 连续页、按需绘制、全文件查找、目录/概览 | 无密码输入、OCR、批注编辑；扫描件无法像文本 PDF 一样查找 | P2 |
| 文件夹 | 虚拟列表、按需目录树、文件导航 | 不跟随符号链接是现有边界；网络目录/权限变化需要实际环境验收 | P3 |
| 归档 | 已接入原生归档浏览，含常见 ZIP/7Z/RAR | 指南仍有旧 ZIP-only/不支持 RAR/7Z 描述，本轮修正；冷门扩展继续按 Roadmap | P3 |
| APK | 当前走原生归档浏览 | 清单解析器仍存在，但格式路由提前返回，绕过详情解析；包名/版本/SDK 未接入此入口。源码确认，未独立实测 | P2 |
| EPUB | spine 顺序、章节切换、图片/字号 | 移除链接与样式，书内导航和出版物排版不完整；无阅读进度 | P2 |
| 字体 | 可编辑样张、字号、字符网格、退出释放 | 浏览器字体支持边界；可变轴/字形覆盖检查不是现有能力 | P3 |
| IPYNB | Markdown/代码及已保存文本、PNG | 无执行，HTML/富输出不展示；每页 40 单元格、5 MB 渲染界限 | P3 |
| XLSM/XLTX/ODS | 当前复用工作簿数据摘录器 | 同类排版缺失，原生处理器覆盖须逐格式确认 | 跟随 XLSX 兼容调查 |

## 后续实施的完成条件

XLSX 不以“文件成功打开”作为完成：应验证安装组件的环境能看到工作表、合并表头、金额/时间/日期、中文字体和常见图片/图表；缺组件时提示清楚且默认打开可用。还需验证连续切换、取消、关闭释放文件、加载失败恢复、位数和 DPI 兼容。

DOCX/PPTX 不以简单一页样本通过作为完成：用上述场景及真实日常文档检查内容完整性和阅读交互。新引擎选择前记录许可、安装依赖、离线能力、体积及资源成本，避免把界面重排误当作格式兼容问题已解决。当前执行状态统一见 [TODO](../development/TODO.md)，延期数据库范围见 [Roadmap](../development/Roadmap.md#快速预览-sqlite-与-sqlcipher-数据库)。
