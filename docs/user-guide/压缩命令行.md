# 压缩命令行

独立的 `One.Cli.exe` 与 `One.exe` 一起发布，开发构建位于 `dist/native/One.Cli.exe`。它不打开主窗口或资源管理器，不启用全局快捷键，也不读取或更改界面的压缩偏好，可以与 One 界面同时运行。同一用户、同一登录会话的归档额度共享，参与实例的三个总预算分别采用较严格值；命令行参数不会绕过界面的共享资源限制。开发构建与正式安装版隔离。

以下示例使用 PowerShell；省略 `archive` 前缀也可以。

```powershell
& 'D:\Program Files\One\One.Cli.exe' archive create --output 'D:\Backup\资料.zip' 'D:\资料'
& 'D:\Program Files\One\One.Cli.exe' archive list 'D:\Backup\资料.zip'
& 'D:\Program Files\One\One.Cli.exe' archive test 'D:\Backup\资料.zip'
& 'D:\Program Files\One\One.Cli.exe' archive extract --output 'D:\恢复' --destination smart 'D:\Backup\资料.zip'
```

相对路径从当前工作目录解析，解压目标文件夹须已存在。创建最多接收 128 个文件或文件夹；列表、校验、解压最多接收 128 个归档，默认按顺序处理；可指定并行度同时运行独立归档，单个失败后继续后续归档。已有压缩包不会被创建操作覆盖。

高条目数、声明展开量、异常已知压缩比或疑似嵌套包会返回退出码 13。JSON 错误记录包含 `risk` 摘要，尚未发布内容。确认可信来源与所需空间后可显式重试，例如 `archive extract --allow-risk --max-extract-gib 128 --max-extract-minutes 120 --output 'D:\恢复' 'D:\Backup\资料.zip'`。批准信息绑定此次读取的源修订，不会保存为全局设置；成功重试在 JSONL 中增加 `risk-approved` 事件。具体判定及固实格式的限制见 [解压风险确认](压缩与解压.md#解压风险确认)。

## 选项

| 选项 | 用途 |
| --- | --- |
| `--output PATH` | 创建的压缩包位置，或解压目标文件夹；创建、解压必填。 |
| `--format FORMAT` | 创建格式：zip、7z、tar、tar.gz、tar.xz、gz、xz。必须与输出后缀相符；tgz 对应 tar.gz，txz 对应 tar.xz。省略时由后缀决定。 |
| `--volume-size SIZE` | ZIP/7Z 分卷大小：整数 bytes 或 KiB/MiB/GiB，例如 `100MiB`。支持 1 MiB–64 GiB。 |
| `--level 0-9` | 创建的压缩等级，默认 6；ZIP/7Z 的 0 为仅存储，其他压缩流按引擎最低档处理。TAR 只接受显式等级 0 或省略。 |
| `--threads auto\|1-64` | 默认 2；自动仅用于 create，按 CPU 与本次总线程预算选择。ZIP 可按文件并行创建；7Z/XZ 创建及 7Z 修改使用线程参数，GZ 为单线程。 |
| `--zip-method deflate\|xz` | 仅创建 ZIP；默认 Deflate，XZ 需要接收软件支持。 |
| `--zip-encryption aes256\|zipcrypto` | 仅创建 ZIP；有密码时生效，默认 AES-256，ZipCrypto 用于旧软件兼容。 |
| `--seven-method lzma\|lzma2` | 仅创建 7Z；默认 LZMA2。 |
| `--solid off\|1…1024\|solid` | 仅创建 7Z；大小仅允许 1、2、4、8、16、32、64、128、256、512、1024 MiB，默认 64；off 为非固实，solid 为完整固实。 |
| `--memory-mib 128-8192` | 每个归档辅助进程的提交内存上限，默认 1024 MiB；全部操作适用。 |
| `--concurrency 1-8` | 本次调用的并行任务数，默认 1。公共队列参数放在 batch 外层。 |
| `--total-memory-mib 128-32768` | 本次调用所有运行任务的进程内存上限合计预算；缺省为 2048 MiB 或最大的单任务上限，两者取较大值。 |
| `--total-threads 1-64` | 本次调用所有运行任务的配置线程数合计预算；缺省为 4 或最大的单任务线程数，两者取较大值。 |
| `--destination MODE` | folder 同名文件夹、smart 智能解压、here 解压至此；默认 folder。 |
| `--conflict POLICY` | here 模式的同名文件处理：rename 自动重命名、skip 跳过、replace 替换；默认 rename，已有目录合并。 |
| `--allow-risk` | 显式允许本次风险解压；适用于 extract，以及需要准备复合包装层的 list/test。不会关闭路径、字节、时间或磁盘检查。 |
| `--max-extract-gib 1-8388607` | 配合 --allow-risk 设置单层实际展开上限，默认 64 GiB；声明大小超限仍拒绝。普通无风险内容也遵守此上限。 |
| `--max-extract-minutes 1-1440` | 配合 --allow-risk 设置解压时限，默认 30 分钟；不包含排队或最终发布。 |
| `--select 0,1,2` | 只解压指定条目；索引从 0 开始，与 list 一致。选中目录包含子项；省略时解压全部。 |
| `--scan` / `--no-scan` | 仅 extract：开启或显式关闭本次恶意软件扫描；默认关闭，两个参数不能同时使用。 |
| `--no-zone` | 仅 extract：关闭本次下载来源标记传递；默认保留 Internet/受限区域标记。 |
| `--encoding CODEPAGE` | ZIP 文件名代码页：auto、437、932、936、950、65001，默认 auto。适用于 list/extract/test/update。 |
| `--changes FILE.json` | 修改单卷或分卷 ZIP、7Z 的计划。 |
| `--jobs FILE.json` | batch 的批处理计划。 |
| `--password-stdin` | 从标准输入读取密码。 |
| `--password-encoding ENCODING` | ZIP 密码编码：utf8（默认）、system、437、932、936、950 或 65001。独立于文件名编码，适用于 create/list/extract/test/update；非 ZIP 只接受默认 UTF-8。 |
| `--json` | 标准输出使用 UTF-8 JSON Lines。 |
| `--progress` | 进度 JSON Lines 输出到标准错误，不混入结果流。 |
| `--help` | 查看帮助。 |

`--` 后的参数全部按路径处理，可用于以 `-` 开头的文件名。未知、重复或不适用于当前操作的选项会报参数错误。`--scan` 和 `--no-scan` 仅用于解压，不更改 GUI 偏好。

资源参数放在具体操作中，batch 可为每个子任务分别指定。内存上限由 Windows 对辅助进程实施，不是 CLI/GUI 总内存或工作集限制；高等级或复杂归档可能超过预算。无法应用限制、明确内存不足时报告资源错误，可提高上限或降低等级重试。所有创建阶段和最终校验沿用同一预算，失败时不发布压缩包。

指定 `--concurrency` 后，任务还须同时满足总内存和总线程预算才启动；按配置额度预留到清单全部输出、修改计划处理、扫描及最终发布结束。单任务超过本次或其他参与实例的总预算返回资源错误 9，不会一直等待。GUI 与其他 CLI 实例共同受共享预算约束，三个总上限分别取存活参与实例中的较严格值；退出后移除该实例的限制。它不是整机内存或系统线程数硬限制。

命令行解压默认将原包的 Internet/受限区域标记传给所有解出的普通文件。来源标记无效或无法读写时失败，不发布最终结果；参数 `--no-zone` 是明确的单次覆盖，不更改 GUI 设置，也不清除现有文件标记。目标磁盘不支持 NTFS 命名流时可选择其他目标，或显式使用该参数。具体范围见 [解压防护](压缩与解压.md#文件关联与长期偏好)。

GZ/XZ 只支持单个文件；目录使用 TAR.GZ/TAR.XZ。TAR/GZ/XZ 不支持密码或分卷。RAR 为只读格式。修改支持单卷和分卷 ZIP、7Z；分卷分别传入末尾 `.zip` 或首卷 `.7z.001`，其他卷放在同一目录。

## 恶意软件扫描

使用 `extract --scan` 在文件发布前通过本机 Windows AMSI 提供者检查暂存文件。默认关闭；`--no-scan` 显式关闭本次扫描，不能与 `--scan` 同时使用。没有可用提供者、扫描失败、超过内存预算或单文件 120 秒时停止发布，不能当成“安全”；空文件不提交内容扫描，威胁和策略阻止同样停止。详细说明见 [恶意软件扫描](压缩与解压.md#恶意软件扫描)。

启用时 result/error 的 JSON 可包含 `scan` 摘要：`state`、`files`、`emptyFiles`，以及可选的 `provider`/`reason`。状态为 passed、empty、incomplete 或 blocked；未开启时没有该字段。提供者超时或进程异常未返回统计时省略 emptyFiles，不将未知数量记为零。files 表示已完成检查的暂存文件数量，不包含当前失败文件；这里扫描的是解出的文件，不是原压缩包。

## 密码

密码输入必须是 UTF-8，最多 1024 字节；允许末尾一个换行，保留前后空格，禁止 NUL 或多行。`--password-stdin` 要求管道或重定向输入。没有 `--password=明文` 参数，密码不会写入参数、日志或暂存。同一次多归档调用使用同一密码。不要把密码直接写进命令历史或任务计划。

标准输入始终是 UTF-8；`--password-encoding` 只决定 ZIP 引擎用哪些字节派生密码，不改变管道编码，也不改变文件名。默认保持现有 UTF-8 行为；Windows 版 7-Zip 的中文 ZIP 密码可尝试 `--password-encoding system`，跨机器时可显式指定相同代码页，例如 `936`。无法无损转换的密码会失败，不替换字符、不自动尝试其他编码。创建后的自动校验、修改前后校验都沿用本次选择；修改不会重新编码保留条目的加密数据，添加项沿用同一密码编码。批处理可给各个 ZIP 子任务分别设置编码，外层仍使用同一标准输入密码。

缺少密码、ZIP 引擎明确报告密码错误、7-Zip 明确报告错误密码时，退出码为 3。某些加密头损坏与错误密码无法可靠区分，会报告归档错误 4，并提示检查内容或密码。

## 修改 ZIP 和 7Z

先用 list 查看索引，再保存 UTF-8 JSON 数组。添加文件的相对路径从修改计划所在目录解析，未知操作或字段会被拒绝。

```json
[
  {"kind":"rename","index":0,"name":"文档/说明.txt"},
  {"kind":"delete","indexes":[2,3]},
  {"kind":"mkdir","name":"图片/"},
  {"kind":"add","source":"输入/封面.png","name":"图片/封面.png","replace":false},
  {"kind":"comment","text":"备份备注"}
]
```

```powershell
& 'D:\Program Files\One\One.Cli.exe' archive update --changes 'D:\Backup\changes.json' 'D:\Backup\资料.zip'
```

共用界面的预检、完整校验和事务替换。读取清单后原包发生变化会拒绝保存，索引以修改前的原始清单为准。最多 10000 项修改、4 MiB 计划；包内路径安全检查与界面一致。

没有独立目录条目的文件夹也可按包内路径操作：`{"kind":"rename-folder","folder":"原目录/","name":"新目录/"}`，或 `{"kind":"delete","indexes":[],"folders":["原目录/子目录/"]}`。`folders` 可与条目索引一起删除，目录操作包含全部子项。文件夹路径按修改前的清单解析，大小写不敏感；同一计划中先移动父目录，再引用原路径修改子目录仍操作原来的对象。不能按此方式引用本次计划刚新建的目录。重命名到其他已存在的文件夹不会自动合并。

7Z 使用相同的 `update --changes` 命令和 JSON 操作，支持添加、删除、重命名及新建目录；不支持 `comment`，上面的示例用于 7Z 时需移除备注项。加密包通过 `--password-stdin` 提供原密码，保留原来的文件名加密模式。固实包的部分删改可能需要重新压缩数据块。

分卷保存先登记恢复索引及新卷来源记录，生成并校验新卷后通过可恢复交接整组发布，支持卷数增减及空包。ZIP 使用观察到的数据卷大小且最低 1 MiB；7Z 使用首卷大小，只有一个物理卷时最低 1 MiB，不保证与创建时原配置完全一致。已经提交但旧副本清理失败仍返回成功，JSONL `result` 增加 `recovery` 路径，文字输出提示副本待清理；可在 One 的恢复资料入口检查并清理，避免重复执行修改。生成中断的已登记暂存支持检查后确认清理；交接/发布中断按完整清单还原或清理；回滚后仍保留新卷暂存的清理依据。旧的无记录暂存、未登记文件或损坏资料会显式保留，不能凭目录名称删除。

## 批量任务

batch 计划是命令参数数组的数组，路径相对计划所在文件夹解析。最多 128 个实际操作、4 MiB 文件。不能嵌套 batch，也不能在子任务中使用帮助、JSON、进度、密码输入或队列参数；公共开关及队列预算放在外层。子任务可以分别设置 `--threads` 和 `--memory-mib`。

```json
[
  ["create","--output","备份.zip","资料"],
  ["test","备份.zip"],
  ["extract","--output","恢复","--destination","smart","备份.zip"],
  ["list","备份.zip"],
  ["update","--changes","changes.json","备份.zip"]
]
```

```powershell
& 'D:\Program Files\One\One.Cli.exe' archive batch --jobs 'D:\Backup\jobs.json' --json --progress
$LASTEXITCODE
```

需要并行时在外层加 `--concurrency 2 --total-memory-mib 2048 --total-threads 4`。独立任务可同时运行；同一归档的读写、压缩源目录与写入位置重叠、以及同一或包含关系的解压目录保持计划顺序。路径会先按实际文件或最近已存在的父目录解析，识别目录别名和大小写；同一分卷归档视为一个来源。无法确认路径时保守地顺序执行。修改任务可引用任意添加源，因此作为顺序屏障，前面的任务结束后运行，后面的任务等待它结束。失败仍释放后续步骤，依赖不会自动跳过；默认并行度 1 保持原有计划行为。

子任务的命令语法全部检查后才开始执行；文件内容、修改计划和引擎预检在对应任务执行时检查。失败后继续后续任务，不自动回滚已完成的其他归档。Ctrl+C/Ctrl+Break 停止后续任务并取消所有正在运行和等待任务的可取消阶段；已完成项保留。最终原件替换阶段等待保护流程结束，不强行中断事务。

## 输出、退出码和日志

JSONL 每行带 `schema:1`，事件为 start、meta/entry（列表）、result 或 error，最后 summary。任务带 job（原计划索引，从 0 开始）、id（与进度关联）、operation、source；result 包含 path/count/skipped 和 elapsedMs，error 包含 message/exitCode。列表分页流式输出，最多 100 万条；收到该任务 result 才代表完整清单已输出。并行输出可能按完成顺序交错，按 job/id 归组；每个任务内部清单顺序保持不变。start 表示进入本次调度，可能仍在等待资源，不代表辅助进程已启动。消费者应检查最后的 summary 和进程退出码。

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部成功，包括按指定冲突策略跳过同名项。 |
| 1 | 未能进一步分类的引擎或操作失败。 |
| 2 | 参数或计划无效。 |
| 3 | 已确认的密码问题。 |
| 4 | 归档损坏、无法打开或读取期间变化。 |
| 5 | 输入文件读取失败。 |
| 6 | 已确认的写入失败或目标冲突。 |
| 7 | 不安全条目或超出安全限制。 |
| 8 | 同时有成功和失败，或不同类别的失败。 |
| 9 | 明确的资源不足或无法应用资源限制。 |
| 10 | 恶意软件扫描未完成。 |
| 11 | 恶意软件扫描检测到威胁或被安全策略阻止。 |
| 12 | 辅助进程失去响应、任务长时间没有进展或解压超过本次时限。 |
| 13 | 需要显式确认解压风险；未发布内容。 |
| 130 | 已取消。 |
| 126 | 启动器找不到运行文件或无法启动。 |

同一类别的全部失败返回该类别退出码，取消优先返回 130。无明确分类时返回 1 或 4，不根据本地化错误文字猜测密码或权限原因。

任务进程每两秒发送内部心跳；30 秒没有心跳，或 30 分钟没有读写及处理进展时，One 停止可取消阶段并回收暂存。解压另受本次解压时限控制；其他持续工作的长任务不会仅因总耗时长而被取消。最终保存与交互拖出等待受保护，不由该超时机制强制终止；恶意软件扫描仍有单文件时限。内部心跳不会写入 CLI 的 JSONL 结果或逐条保存到日志。

日志记录本次队列预算、操作类别、结果、耗时、退出码和受限的扫描摘要，保存于 One 配置下的 `logs/cli.jsonl`，可在 **设置 → 备份与日志** 查看、导出。不保存密码、完整参数、文件内容或输入文件名。开发运行使用 `work/cli-profile`，独立于 dev 和正式配置。每次运行的临时缓存在正常退出时回收；强制结束或断电后的暂存回收仍需后续完善。

ALZ 只读支持单卷 v10 的存储、Deflate、BZip2 / DLZ。`--encoding auto` 对 ALZ 使用 CP949，也可显式指定 `--encoding 949` 或 `65001`；ALZ 密码沿用文件名编码。`--password-encoding` 仍仅用于 ZIP。分卷及数据描述符不开放。
